## 0. 한 페이지 요약: 문제·해결 흐름·통과 조건

**‘목소리 크기 + 발음 + 높낮이’를 사용자가 골라, 같은 생활 발화를 짧게 연습하고 시각적으로 비교하는 앱**을 설계한다. 세 항목을 모두 끝내야 하는 코스는 아니다. 다른 의사소통 방식을 대체하거나 구어 사용을 권하지 않는다.

| 영역 | 핵심 흐름 | 아직 말할 수 없는 것 |
|---|---|---|
| 크기 | 개인 참고 발화 → 같은 조건에서 말하기 → 상대 입력 크기 비교 → 한 번 재시도 | 어디서나 적절한 음량·절대 SPL |
| 발음 | 검수한 목표소리 → 제한된 단어 말하기 → 검증된 소리 후보를 시각 비교/보류 → 한 단서로 재시도 | STT 기반 정오·범용 음소진단·치료 효과 |
| 높낮이 | 자기 기준 → 올리기/내리기 시도 → 유성구간 상대 F0 곡선 → 전후 비교 | 정상 피치·억양 적절성·의사소통 개선 |

현재 근거는 전문가 자문에서 보고한 음량 확인의 어려움까지이며, 세 모듈 앱의 실제 이용 수요·발음 자동비교의 신뢰성·소통 개선 효과는 입증되지 않았다. 가장 큰 위험은 **한국어를 쓰는 성인 청각장애인·난청인의 실제 발화를, STT 정답률에 기대지 않고, 잘못 지적하지 않으면서 시각적으로 피드백할 수 있는가**다. 발음은 핵심 모듈에서 빼지 않으며, 이 위험을 먼저 검증하는 게이트를 둔다.

권고하는 순서는 다음과 같다.

1. 이 설계와 검증 계획에 대한 교수 검토 → 사용자 승인.
2. 세 모듈의 필요성 확인 및 발음 엔진·데이터·권리·iPhone 입력의 **타당성 조사/승인된 기술 실험**.
3. 통과한 범위만 연구용 프로토타입으로 구현 → 실제 당사자 비교 평가.
4. 세 모듈의 핵심 조건이 통과해야 ‘세 항목 자율훈련 앱’으로 제품화 판단.

발음 게이트가 실패하면 STT·재청취만 붙여 성공한 것처럼 출시하지 않는다. 제품 개발을 보류하고, 발음 접근 재연구 / 전문가 보조형 별도 서비스 / 사용자가 명시적으로 승인한 축소안을 선택한다. 교수 AI 역할의 설계 승인은 **검증할 가치와 실행 계획의 승인**이지, 정확도·치료 효과·수요를 인증하는 승인이 아니다. **다음 실행 범위도 사용자 승인 후 정한다.**

## 1. 대상, 문제, 목표와 비목표

### 1.1 초기 대상과 사용 순간

- 한국어 구어를 사용하며, 자신의 음량·특정 발음·높낮이 중 하나 이상을 **본인이 연습하고 싶어 하는 성인** 청각장애인·난청인.
- 조용한 공간에서 혼자 휴대전화를 고정하고, 실제로 자주 쓰는 짧은 말 한 개를 연습하는 상황부터 시작한다.
- 청력 손실 시점, 보장구, 듣기 능력, 구어 경험을 하나의 특성으로 묶지 않는다. 연구 시 결과 해석에 필요한 최소 정보만 선택 수집한다.
- 수어·필담 사용자에게 구어 훈련을 요구하지 않는다. ‘비장애인처럼 말하기’가 제품 목표가 아니다.

### 1.2 풀려는 문제와 목표

| 문제 | 목표 | 성공을 주장할 수 있는 범위 |
|---|---|---|
| 자기 느낌과 타인이 듣는 음량이 다른 사례, 반복 확인의 부담 | 같은 기기·조건에서 개인 참고 발화 대비 크기 변화를 시각적으로 이해 | 재현·상대 조절을 도왔는지. 보편적으로 적절한 음량이라는 뜻 아님 |
| 집에서 발음 피드백을 확인할 사람이 없는 경우 | 제한된 발음 대비에서 분석 가능한 부분만 시각 비교하고 한 가지 연습 단서 제시 | 평가한 음소·낱말·대상·조건에 한정. 종합 발음 진단 아님 |
| 높고 낮은 소리의 변화를 눈으로 확인해 보고 싶은 잠재 수요 | 자기 기준 F0 변화 방향을 시각적으로 연습 | F0 변화 조절. 억양 적절성·청자 이해·임상 개선과 구분 |
| 반복 연습 시 무엇을 바꿀지 알기 어려울 수 있음(가설) | 한 항목 → 한 변화 → 재시도 → 전후 비교의 짧은 흐름 | 실제 당사자에게 부담보다 유용성이 큰지 별도 비교 |

### 1.3 비목표·실패로 볼 동작

- 치료·진단·장애 판정·재활사 대체·발성 안전성 검사·치료 효과 보장.
- 실시간 회의 보조, 다자 화자 분리, 일상 대화 상시 녹음, 소음 속 정확한 자기 음압 측정.
- 보편적인 상황별 dB 정답, 성별 정상 피치, 사투리/개성의 오류 판정, 점수·순위·강제 출석/연속 학습.
- STT 문장 일치 → 발음 정상, STT 실패 → 발음 오류라는 등치.
- 장시간 큰 소리·극단적인 높낮이·참고인을 무조건 따라 하도록 유도. 불편하면 즉시 중지하며, 지속적인 통증·쉰 목소리 등은 앱 판단 없이 전문가 상담을 안내한다.
- 분석 불가를 사용자 실패로 표시하거나, 정확도를 높이기 위해 분석 가능한 이용자만 숨겨서 보고하는 것.

## 3. 접근안 비교와 선택 이유

## 5. UX와 세션 상태 설계

### 5.1 기본 흐름

`항목 선택 → 연습할 말 선택 → 시각 목표·조건 안내 → 마이크 준비 → 짧게 말하기 A → 결과/분석불가 → 한 가지 바꿔 B(선택) → A/B 비교 → 종료/명시 저장`

1. **홈**: 세 항목과 간단한 목적. 승인/검증 전 모듈에는 ‘검증 중—사용 불가’를 표시하며 작동하는 척한 시연 점수를 넣지 않는다. 최종 제품에서 세 항목을 제공할 수 있는지는 게이트 결과에 달린다.
2. **연습 발화**: 공통 생활 문장과 그 문장에 포함된 짧은 발음 단어를 연결한다. 같은 문장을 모든 음소 훈련에 억지로 쓰지 않는다. 기본 후보는 4개 생활 문장·12개 단어·2개 발음 대비이며, 실제 구성은 당사자 필요와 엔진 지원 확인 후 확정한다.
3. **목표 안내**: 음량은 ‘참고 발화와 비슷하게/조금 작게/조금 크게’, 발음은 검수한 발음 대비와 글자-소리 차이, 높낮이는 ‘처음 측정 가능한 소리와 마지막 소리의 높이 차이 보기’. 목표 자체가 적절성·진단·치료 처방은 아니다.
4. **준비**: ‘지금 마이크가 켜져 있음’ 표시. 휴대전화 위치를 정하고 고정하도록 돕되 1m를 정답으로 강제하지 않는다. 예: 팔 길이보다 가까운 탁상 배치 후보를 시험해 정함. 위치·방향·마이크 경로가 바뀌면 재기준 필요.
5. **발화**: 사용자가 시작/완료 버튼을 누른다. 초깃값 최대 8초, 시간 안내는 시각적. VAD는 보조 경계이며 무성 자음·작은 발화를 잘라 버리는 자동 종료의 유일 근거가 아니다.
6. **결과**: 핵심 한 항목만 크게. ‘측정된 변화’ / ‘기기의 추정’ / ‘다음 연습 제안’을 다른 문구로 구분한다. 다른 항목의 자동 지적을 끼워 넣지 않는다.
7. **재시도**: 한 단서만 선택. ‘그만하기’가 동등하게 보인다. 다시 말할 의무·실패 횟수·종합 성적 없음.
8. **전후**: 같은 발화·입력 fingerprint·기준·분석 버전일 때만 나란히 비교. 다르면 ‘조건이 달라 직접 비교할 수 없음’. 재청취는 선택형 부가이고 시각적 피드백을 대체하지 않는다.

### 5.3 접근성·표현 원칙

- 소리만으로 시작/완료/오류를 알리지 않는다. 색+텍스트/형태를 함께 쓴다.
- 큰 글자, 충분한 대비, 주요 터치 영역 44×44 CSS px 이상(팀의 사용성 시작 목표), VoiceOver 레이블, 200% 글자 확대·좁은 화면·가로 화면·키보드 접근 검증. 스크린리더에 매 프레임 숫자를 쏟지 않고 상태 전환/완료 요약만 알린다.
- 동적 그래프는 일시정지/완료 후 정적 확인 가능. 눈으로 계속 쫓아야만 성공하는 흐름을 피한다.
- ‘정상/비정상’, ‘당신은 틀림’, ‘발음 00점’ 대신 ‘기기가 이 부분을 비교하기 어려움’, ‘이번 입력에서 ○○ 후보로 추정’을 사용한다.
- 발음 교재의 조음 그림·글 설명은 목표 이해용이며, 음성만으로 혀·입술 위치를 알아냈다고 말하지 않는다.

## 6. 모듈별 알고리즘과 품질 계약

### 6.0 공통 오디오·품질 계층

원본이란 **브라우저가 제공한 PCM**이며 하드웨어 이전 원시 음압이라는 뜻이 아니다. 요청한 AGC/잡음억제/반향제거와 실제 `getSettings()` 값을 각각 기록한다. 값이 false여도 숨은 장치 처리를 배제할 수 없다(E09).

- 입력을 단일 캡처에서 나누되 경로를 구분한다: ①브라우저 PCM 기반 분석/발화 버퍼 ②RNNoise+VAD 품질 보조. 전후 처리 신호를 혼용하거나 다른 경로의 수치를 비교하지 않는다.
- 후보 초기 프레이밍: 10ms 수신 단위, 음량 요약 50ms, F0 창 40–60ms·hop 10ms. **전부 기술 실험 시작값이며 검증된 임상 기준이 아니다.** 실제 지원 대역·시간분해능에 따라 평가 후 버전을 고정한다.
- 발음 녹음은 무성 자음 보존을 위해 사용자가 정한 전체 구간+준비 후 250ms 앞 여유/350ms 뒤 여유를 후보로 한다. VAD의 침묵 판정만으로 음소를 제거하지 않는다. 준비 이전 소리는 수집하지 않는다.
- `sessionId/attemptId/epoch/settingsRevision/sampleStart/sampleEnd`로 순서·중복·누락·지연·조건 변경을 검증한다. 순서가 틀린·NaN·시간 공백·clipped·stale 입력에는 이전 정상값을 정답처럼 유지하지 않는다.
- VAD는 ‘말 같은 소리’일 뿐 사용자 신원이나 청자 이해를 보장하지 않는다. 혼자 연습하는 조건을 기본으로 하며 타인/TV가 섞이면 취소를 요청한다. 자동 혼입 검출은 미확보이므로 탐지 보장을 하지 않는다.
- 정상 완료/8초 한도에서는 마지막 post-roll 뒤 입력 track·노드·타이머를 해제한 다음 고정 PCM을 분석한다. `analyzing/result/abstain/error`는 새 샘플을 수집하지 않는다. 준비만 된 상태도 30초 후 자동 중지한다. 재시도는 새 사용자 클릭과 실제 입력설정 확인을 요구한다.
- 결과 품질: `valid`(허용 범위에서 비교) / `limited`(가능한 부분만, 금지 해석 명시) / `abstain`(피드백 보류) / `error`(기술 실패). `limited`를 실패 음소의 확신도 낮은 오지적 통로로 쓰지 않는다.
- 수치가 없어도 완료/중지 흐름은 가능해야 한다. 진단 로그에는 PCM·전사·기기 실명/영구 deviceId를 넣지 않는다.

### 6.1 목소리 크기

**측정 구간과 선택편향 방지 계약**

1. 같은 고정 배치에서 편안하게 말한 같은 짧은 말 2개를 참고 발화로 취득한다. 자동으로 ‘적절한 소리’라고 이름 붙이지 않는다.
2. **집계 구간은 사용자가 누른 발화 시작~완료의 전체 구간**이다(앞/뒤 여유 버퍼는 제외). 유한한 모든 표본을 포함하여 `L=10·log10(sum(x²)/N)`의 전체 구간 입력 에너지를 구한다. 50ms 프레임 분포는 참고 표시일 뿐, 낮은 에너지·VAD 비발화 프레임을 빼고 큰 프레임만으로 대표값을 다시 계산하지 않는다. 이것은 음성만 분리한 음압이 아니라 침묵·잔여 잡음을 포함하는 **정해진 구간의 브라우저 입력 크기**다.
3. 품질 mask는 비교 허용 여부를 정할 뿐 에너지가 낮다는 이유로 표본을 골라 집계하지 않는다. NaN/누락/클리핑/일부 발화 손실이 있으면 **시도 전체를 보류**한다. 작은 신호를 잘라 남은 큰 신호로 목표 도달을 만드는 경로는 없다.
4. 같은 말·동일 배치·입력경로·집계법에 한해 `ΔL=L_attempt−L_reference`를 비교한다. 초기 비교 조건은 발화 구간 길이 차이≤10%, 내용/일부 손실 없음, VAD 보조로 추정한 발화 점유율 차이≤10%p다. 이 값은 기술검증에서 확정할 팀의 시작값이다. VAD가 작은 말을 놓쳐 품질 보류가 늘어나는 현상도 gain별로 보고하며, 그 표본을 평가분모에서 지우지 않는다.
5. 준비/마무리의 비발화 후보 구간 각 최대 250ms로 배경 입력을 추정한다. 그 구간에 말/외부 소리가 있거나 불안정하면 보류한다. 후보 조건은 배경 전후 변화≤3dB, 집계구간/배경 추정 에너지비≥10dB다. 이는 진짜 SNR을 확정하는 식이 아니라 비교 품질의 경험적 시작 gate다. 배경을 정확히 분리했다고 주장하거나 검증 없이 에너지를 빼지 않는다. 고정 잡음 속 작은 발화가 이 gate를 통과하는지는 T05에서 시험한다.
6. `+114`나 기존 4상황 범위를 사용하지 않는다. 디지털 상대 변화(dB 차이)일 뿐 절대 SPL/dBA·사회적 적정 음량이 아니다. AGC true/unknown 경로는 기본적으로 목표 피드백 보류이며, 따로 잠금 시험한 기기/OS/입력경로에서 T05 전체 조건을 만족한 경우만 명시 지원할 수 있다. 설정 false만으로 실제 음압 신뢰성을 보증하지 않는다.
7. 참고 두 발화의 크기/시간/배경 변동이 큰 경우 재취득한다. 다른 내용·거리·방향·처리·입력 변경은 비교 불가다. 사용자가 위치 유지를 확인했다고 물리적 동일성이 보증되는 것은 아니다.

**목표의 의미**

- 기본은 ‘내가 저장한 이 발화의 입력 크기 익히기’. ‘적절하게 말함’ 판정이 아니다.
- 실제 생활에 적절한 목표를 원하면 당사자가 선택한 협력 청자/전문가와 정한 참고 발화를 별도로 사용할 수 있도록 설계하되 검증 후 선택 제공한다. 도우미가 없어도 자기 비교는 가능하지만 적절성을 확인했다고 주장하지 않는다.
- ‘조금 더 크게/작게’는 사용자가 선택한 실험 목표다. 목표 띠는 참고 반복 변동과 실험으로 정하고 버전 고정한다. 값이 너무 작으면 먼저 마이크/거리/품질을 확인하며 무조건 크게 내라고 지시하지 않는다.
- A/B는 전체 구간 길이·집계 표본 수·품질 탈락 사유·배경 변화·발화 점유율을 함께 확인한다. 조건이 다르면 크기 차이/개선 화살표를 숨기고 재기준 또는 종료를 제시한다.

**T05 전체 경로 시험과 실기기 기준**

- 디지털 합성뿐 아니라 **같은 현실적 발화 파형**(약한 모음/무성 자음·짧은 음절 포함)에 ±3/6dB gain, 일부만 약화/소실, clipping, 고정 잡음+음성만 gain, 음성/잡음 함께 gain, AGC 압축을 적용한다. 실제 품질 판단·VAD·구간 집계를 거친 출력과 모든 보류를 기록한다. 알려진 전체 구간 gain의 디지털 오차≤1dB·방향 일치≥95%라는 기존 기준을 유지한다.
- 실기기 재생 시험은 휴대전화와 독립적인 고정 참조 마이크/레코더(AGC/리미터 없는 상대 응답을 먼저 검증)로 같은 시도의 실제 입력 변화 `ΔL_ref`를 기록한다. 재생기 명령 gain만을 실제 소리 정답으로 쓰지 않는다. 실제 발화도 같은 고정 참조 경로로 구간을 동기화한다. 참조 경로/구간 불확실은 앱 성공으로 집계하지 않고 실험 자체 미결정으로 기록한다. 절대 SPL 교정을 요구하거나 보증하는 방식이 아니다.
- 각 기기/OS/처리·입력경로별 **사전 적격 paired trial 전체**가 분모이며 앱의 보류·오류도 포함한다. `|ΔL_ref|≥3dB`인 비교에서 앱이 같은 부호의 `|ΔL_app|>1dB`를 내면 방향 정답, ±1dB 안은 ‘변화 판별 어려움’, 반대 부호>1dB는 **역방향 오안내**다. 고정 입력의 반복 오차/기준 변동으로 deadband가 성립하는지도 먼저 확인한다.
- 초기 실기기 지원 gate: 방향 정답≥95%(95% 하한≥90%), 역방향 오안내 0건(95% 상한≤5%), 비교 피드백 coverage≥80%, 유효 출력의 `|ΔL_app−ΔL_ref|` 중앙값≤2dB. 커버리지가 높아도 역방향이 있으면 통과하지 않는다. 사람·세션 군집을 고려한 신뢰구간과 조건별 결과를 보고하며 충분한 표본을 확보하지 못하면 미결정이다. 수치는 팀의 공학 제안이다.
- 거리/경로 변화·일부 소실·클리핑 시험은 목표 도달이 아니라 **비교 보류**가 기대 결과다. AGC가 실제 6dB 변화를 1dB로 압축하면 방향 성공으로 세지 않으며 그 경로는 미지원/재검증한다. 알려진 변화가 없는 반복 시도에서는 오차 deadband와 허위 목표도달도 별도 보고한다.

### 6.2 발음 — 핵심 기술 타당성 게이트

**기능 계약**: 바름의 ‘글자/목표소리→말하기→시각 비교’ 원리를 참고하되, 자동분석 결과를 무조건 들린 발음의 정확한 전사처럼 제시하지 않는다. 지원된 대비·단어에 한해 ‘기기가 비교한 소리 후보’와 불확실성을 보여준다. 음소 오류 확정·진단·전체 발음 점수는 제공하지 않는다.

#### P0. 엔진과 데이터가 확보되기 전

확정된 발음 엔진·API·모델이 **아직 없다**. 이 설계는 ‘이미 있는 모델을 붙이면 된다’는 구현 설계가 아니다. 먼저 다음을 확인해야 한다(T03).

- 한국어 입력, 목표 음소 inventory/시간 정렬, 후보 음소 간 구별 근거를 얻을 수 있는가. 글자 STT 결과만 주는 엔진은 발음 평가 엔진으로 불합격.
- 한국어 청각장애인·난청 성인 발화에서 별도 검증 가능한가. 일반 한국어 ASR, 외국인 한국어 학습자, 비장애인 정확도를 이전하지 않는다.
- 로컬 iOS Safari에서 실행 가능한 크기·추론시간·메모리/발열인가. 아니면 서버 경로가 필요하다는 사실과 비용·업로드 동의를 사용자에게 다시 제시한다.
- 코드·모델 가중치·학습/평가 데이터·발음 교재·시각 자료의 사용/수정/배포/상업적 사용 조건을 각각 확보하는가. 바름 엔진 접근권은 가정하지 않는다.

P0는 다음 작은 산출물로 나눈다. 조사/실행 담당자가 증거와 다음 차단점을 기록하고 기술 검토자가 확인한다. 사용자 승인 전에는 설치/실행하지 않는다.

P0 보고서의 고정 필드: `하위 gate / 담당·검토자 / 후보·정확 버전·hash / 권리 근거 / 입력 출처 / 실제 출력·지원 대비 / 환경·자원·지연 / 확인됨·미확인 / 차단점 / 통과·실패·미결정 / 다음 결정 승인`. 조사 범위를 소진하면 기술 검토자가 실패/미결정 사유를 사용자에게 보고하고 범위·플랫폼·연구 계속 여부를 결정받는다. 후보가 없는데 무기한 UI 본개발로 우회하지 않는다.

#### P1. 제한된 콘텐츠와 참조 정답

- 기본 연구 단위는 생활 단어에 포함된 **2개 이하의 음소 대비**. 어느 대비가 필요한지는 당사자·재활사 검토와 엔진/데이터 적합성을 함께 보고 정한다. 예시로 파열음 대비를 떠올릴 수 있지만, 현재 대상에게 그 오류가 흔하다고 단정하지 않는다.
- 단어 표기, 하나 이상의 허용 목표 발음, 음절·음소 경계의 후보, 소리변동/방언 허용 범위, 간단한 시각 목표·설명 출처를 사람이 검수한다. 한글 자모 단순 분해를 실제 음소 정답으로 쓰지 않는다(E12).
- 음소 대비가 문맥상 중화되거나 음향적으로 구별할 수 없는 항목은 평가 대상에서 제외한다. 오류율을 낮추기 위해 사후에 어려운 집단을 빼는 것과, 평가 불가능한 항목을 사전에 정의하는 것은 구분한다.

#### P2. 자동비교 연구 파이프라인(후보, 검증 전 확정 아님)

1. 전체 짧은 발화의 품질/발화 일치 가능성을 확인한다. 무음·다른 문장·겹침 의심·지원 밖이면 보류한다. STT는 발화 선택/기기 전사 참고에만 사용할 수 있고 음소 정오의 정답으로 쓰지 않는다.
2. 음소 posterior/likelihood를 제공하는 한국어 모델로 **목표 발음 정렬과 자유/경쟁 발음 경로**를 함께 계산하는 접근을 우선 조사한다. 목표 문자열만 강제정렬하면 실제 없는 음소도 끼워 맞출 수 있으므로 정렬 성공만으로 통과시키지 않는다.
3. 각 지원 구간의 목표 대 경쟁 후보 차이, 경계 안정성, 발화 길이, 모델/반복 간 일관성 등으로 비교 가능성을 판단한다. GOP류 수치는 내부 연구 feature 후보일 뿐 그 자체를 확률/점수/임상 기준으로 표시하지 않는다(E11).
4. 보정 데이터에서 구간별 임계값과 보류 규칙을 고정하고 **다른 화자의 잠금 평가셋**에서 검사한다. 근거 없는 softmax 0.9를 ‘90% 정확’이라고 표시하지 않는다.
5. 통과한 대비에서만 `target_like / contrast_candidate / abstain`을 생성한다. `target_like`는 **지원된 그 대비에서 목표와 가깝다는 긍정적 추정**이므로 오류 후보와 별도의 거짓 수용 gate를 통과해야 한다. 통과해도 문장 전체/사용자 발음 정상 보증이 아니며 초록색 종합 성공·100점으로 바꾸지 않는다.
6. 화면은 단어 내 위치·목표소리·비교 후보·다음 시도할 교육용 단서 한 개를 제시한다. 모델 결과만으로 개인의 혀 위치·호흡 문제를 추론하지 않는다. 설명은 검수된 콘텐츠에서 가져오며 LLM이 임의 교정 처방을 생성하지 않는다.
7. A/B 모두 같은 지원 범위·품질일 때만 후보 변화를 나란히 보여준다. 모델이 바뀌거나 한쪽이 보류면 개선/악화 화살표를 만들지 않는다.

#### P3. 평가 정답과 오류 비용

- 동의한 실제 대상자의 자연 발화를 포함한다. 직원의 과장된 오발음·합성 음성·일반 화자는 기술 smoke test일 뿐 실제 대상의 검증 대체물이 아니다.
- 발음 판단은 2인 이상 한국어 말소리 평가가 가능한 전문가가 블라인드로 구간 라벨/분석 가능/불확실을 독립 표기한다. 불일치율과 합의 절차를 기록하며, 합의 불가능 구간을 모델 정답으로 억지로 만들지 않는다.
- 발음 라벨과 별도로 **낯선 청자의 내용 이해**를 측정한다. 전문가는 익숙해서 알아들을 수 있고, 명료도는 음소 라벨과 다르다(E03/E04).
- 정상/허용 발화를 잘못 지적하는 것과 실제 대비 오류를 목표와 가깝다고 잘못 안심시키는 것 모두 통과 조건이다. 아래 혼동표·분모를 잠그고 지원 대비별·화자별 결과와 신뢰구간을 보고한다. 적게 말해 높은 precision만 얻거나 오류 발화에만 보류하는 엔진은 불합격이다.

**T04 정답·출력·분모 계약**

- 전체 제출 집합 `S_all`: 지원/불확실/품질 거절/오류를 포함한 모든 평가 시도. 사전 지원 prompt·대비·입력조건과 **독립 전문가의 분석 가능 라벨**로 eligible을 정의하며 모델 확신·실행 성공·결과에 따라 사후 제외하지 않는다. 사전 적격인데 앱이 품질 거절한 구간도 eligible의 `abstain`에 남는다.
- eligible 참조 라벨: `A=목표/허용 변이`, `E=미리 정한 대비 오류`. `U=전문가 불확실`, `O=지원 밖`은 별도 안전셋이다. 알려진 미지원 prompt는 metadata 단계에서 반드시 보류한다. 대비 후보가 여러 개면 세부 후보 라벨까지 맞아야 정답이며 다른 오류를 짐작해 맞힌 것으로 세지 않는다.

| 참조 라벨 × 앱 출력 | `target_like(C)` | `contrast_candidate(D)` | `abstain(H)` | `error(X)` |
|---|---|---|---|---|
| A (허용, N_A) | 목표유사 정답 C_A | 오지적 D_A | H_A | X_A |
| E (대비 오류, N_E) | **거짓 수용 C_E** | D_E_match(후보 정답) + D_E_wrong(후보 불일치) | H_E | X_E |
| U/O (N_U/N_O) | 확신 출력 안전 실패 | 확신 출력 안전 실패 | 기대 보류 | 기술 오류(유용한 보류로 포장 안 함) |

- 각 행의 합은 해당 N과 일치해야 한다. E행은 `N_E=C_E+D_E_match+D_E_wrong+H_E+X_E`다. 오지적=`D_A/N_A`, 거짓 수용=`C_E/N_E`; 오류후보 precision=`D_E_match/(D_A+D_E_match+D_E_wrong+D_U+D_O)`; 목표유사 precision=`C_A/(C_A+C_E+C_U+C_O)`. eligible 이외의 확신 출력은 따로 안전 실패이며 정확도 분모에서 숨기지 않는다.
- 오류 검출 recall=`D_E_match/N_E`, 목표유사 정답 recall=`C_A/N_A`; coverage=`(C_A+D_A+C_E+D_E_match+D_E_wrong)/(N_A+N_E)`, 군별 coverage=`(그 군의 모든 C/D 출력)/N_g`. H/X는 recall·coverage의 정답 분자에 들어가지 않으며 분모에는 남는다. 분모가 0인 precision은 ‘정의불가’이고 통과가 아니다.
- 제안하는 동시 통과 기준: **두 출력의 precision 각각≥90%, 95% 하한≥80%; 오지적/거짓 수용 각각≤5%, 95% 상한≤10%; A/E 각 정답 recall≥50%, 각 coverage≥50%**. 전체 평균만 통과해 특정 대비/사람 군의 실패를 숨기지 않는다. 사람별 결과·미지원군/실패군을 공개하고 지원 범위를 사전 정의한다.
- U/O 안전셋에서는 확신 C/D 출력 **0건이면서 95% 상한≤5%**여야 한다. 작은 0/N을 완전 안전으로 해석하지 않는다. metadata상 미지원에는 확신 출력 0건이 회귀 불변조건이다. 독립 라벨 합의가 안 되는 구간에 ‘목표유사’를 강제로 부여하지 않는다.
- 신뢰구간은 자연 발화 분포에서 사람/세션 군집을 반영해 사전 정의한다. 모수·계산/표본계획을 시험 전에 통계 검토하고 잠근다. 실제 오류가 드물어 분모/구간이 부족하면 **미결정**이며 challenge 셋 수치로 자연환경 precision을 대신하지 않는다. 0건 사건에 단순 재표집이 [0,0] 구간을 돌려준다고 완전 안전으로 보지 않으며, 희소/0건에 보수적인 사전 지정 구간을 사용해야 한다.

**판정 규칙의 문서 수준 반례 검사(실제 성능 결과 아님)**

| 인공 출력 사례 | 기존 표면 지표 | 새 gate의 결과 |
|---|---|---|
| A 1,000개 전부 C; E 1,000개 중 D=100/C=900 | D precision 100%, 오지적 0%, 전체 coverage 100% | C precision=1000/1900=52.6%, 거짓 수용=90%, E recall=10% → 실패 |
| A/E 각 1,000개 전부 H | 확신 오지적 0건 | 군별 coverage/정답 recall=0%, precision 정의불가 → 실패/평가 미결정, 통과 불가 |
| A 1,000개만 C, E 1,000개 전부 H | C precision 100%, 전체 coverage 50% | E coverage/recall=0% → 실패 |
| U 100개에 전부 C 또는 D | eligible 성능 표에서 빠질 수 있음 | 안전셋 확신출력=100% → 실패 |

- P0~P3 실패 시 ‘발음 모듈 완료’라고 표시하지 않는다. 시각 목표 안내·선택 재생만 존재하면 **콘텐츠 탐색 시제품**으로 명명하고 자율 발음피드백 성취로 계산하지 않는다.

### 6.3 목소리 높낮이

**목표와 계산을 일치시킨 제한 범위**

- 초기 기능은 **처음 측정 가능한 유성구간과 마지막 유성구간의 높이 차이 보기**다. ‘문장 종결부의 국소 상승/하강’, 억양의 올바름을 판정하지 않는다. 전체 시작→끝 차이와 문장 끝의 움직임은 다른 값이므로 UI·콘텐츠·결과 이름을 모두 이 범위로 통일한다.
- 후보는 YIN 계열 로컬 F0 추정이며 구현/라이선스는 미선정이다(E10). 브라우저 PCM의 에너지·주기성·음성 가능성·클리핑·신선도를 확인한다. 주기적 기계/반주도 F0를 갖지만 사용자의 유성 발화가 아니므로 표시 허용 근거가 되지 않는다.
- 참고 발화 유효 F0 중앙값 `F0_ref`에 대한 `12·log2(F0/F0_ref)`를 시각화한다. Hz는 선택 상세정보다. 성별/장애별 정상 범위·사투리 오류는 부여하지 않는다. 검색 대역 밖·옥타브 의심·불규칙 발성은 보류/범위 재검토한다.
- 방향 계산용 `startWindow/endWindow`는 전체 발화의 첫/마지막 안정 유성 run 각각에서 연속 150ms(초기 후보)다. 두 창이 겹치거나 한 창이 부족하거나 경계가 불명확하면 방향은 보류한다. 결과는 두 창의 표본시각과 `12·log2(median(F0_end)/median(F0_start))`를 함께 보존한다. **이것을 ‘끝을 올렸다’로 이름 바꾸지 않는다.**
- 비교 그래프는 실제 경과시간과 무성/보류 공백을 보존한다. 나란히 보기의 0–100% 시간축은 표시 정규화일 뿐 다른 음절끼리 강제 DTW 정렬해 성공을 만들지 않는다. 같은 prompt/입력조건·충분한 유성 증거가 아니면 전후 방향 비교를 보류한다.
- 종결부 국소 억양 훈련은 별도 후속 기능이다. 필요성이 확인되면 목표 단어/음절 구간 정렬·국소 기울기·허용 패턴의 독립 검증부터 새로 설계한다. 현재 전체 차이 계산으로 대체하지 않는다. 멜로디 모방·F0 조절을 소통 효과로 동일시하거나 특정 질환 치료의 낮은 피치 목표를 전용하지 않는다.

**T06 정답·분모·차단 조건**

- 평가용 10ms 시간격자에서 독립 참조 라벨을 `V=유성/F0 추적 가능`, `UV=무성·숨·비음성 잡음`, `U=불확실`로 둔다. 정답 F0가 있는 합성 신호와, 2인 이상의 훈련된 평가자가 파형·스펙트로그램/배음·주기 추적을 검토한 실제 대상 발화를 분리한다. 후보 알고리즘의 출력을 그대로 정답으로 재사용하지 않는다. 서로 다른 오프라인 도구는 보조이며 독립 정답이 아니고, 사람 불일치 구간은 U로 보존한다.
- 유성 coverage=`유효 F0를 낸 V 프레임/N_V`(보류·실패를 분모에 포함). F0 오차는 참조와 출력 모두 있는 V에서 반음 단위로 계산하되 coverage와 반드시 함께 보고한다. 허위유성=`확신 F0를 낸 UV 프레임/N_UV`, 불확실 확신출력=`확신 F0를 낸 U/N_U`다. 앱이 ‘유효’라고 고른 프레임만 평가분모로 삼지 않는다.
- 초기 동시 gate: V의 median 절대오차≤0.5반음, 절대오차>1반음인 gross error≤5%, 옥타브 오류≤2%, V coverage≥60%, 처음/마지막 창의 독립 정답 방향 일치≥90%(보류 포함 적격 시도 전체 분모). 옥타브 오류는 반음 오차의 절대값이 12·k±1(k≥1)에 들어간 V 출력이다. 큰 비옥타브 오류도 gross error로 잡는다.
- **UV의 허위 F0≤2%(95% 상한≤5%)**, U에 대한 확신출력 0건(95% 상한≤5%)도 요구한다. 알려진 무음/metadata상 비음성 fixture는 유효 F0 0개가 회귀 조건이다. 표본·주석 신뢰가 부족하면 미결정. 사람/신호/조건별 결과를 분리하고 주석 불일치·전체 U 비율을 숨기지 않는다. 수치·주석 지침·방향 deadband·표본/신뢰구간 방법은 T06 착수 전에 잠근다.

| fixture(방향을 위해 창별 150ms 이상 있다고 가정) | 기대 출력/판정 |
|---|---|
| 100→200→150Hz | 처음 대비 마지막은 +7.0반음. **종결부 상승/끝 올리기 성공 판정 없음**; 중간 200→끝 150은 내려감을 그래프에 그대로 표시 |
| 100→200→200Hz(끝 평탄) | 전체 처음/마지막 차이만 표시. 끝에서 올라갔다는 단정 없음 |
| 말 끝 무성 자음/긴 공백 | UV/공백에 선/0Hz 없음. 마지막 유성창 시각을 표시; 충분한 창이 없으면 방향 보류 |
| 주기적 기계잡음/반주만 있음 | 음성/품질 gate가 보류; 주기 존재만으로 사용자 F0 출력 금지 |
| 한 구간에서 100→200Hz 옥타브 도약 추정 | 독립 정답이 100이면 옥타브/gross error로 집계·해당 창 방향 보류. 사람이 실제 200으로 바꾼 경우는 별도 정답 |
| 평가자도 주기/유성 여부 불확실 | U로 남겨 확신출력 안전셋 검사; 정답 숫자를 발명하지 않음 |

## 7. 독립 제품의 기술 선택과 기존 코드 참고 경계

### 7.1 읽기 범위와 문서 불일치

기존 코드는 이미 구현된 입력의 실패·정리 패턴과 실험상 한계를 배우기 위한 참고다. 재사용 비율은 목표가 아니며, 새 제품의 문제정의·화자등록·상황선택·아키텍처를 기존 자산에 맞추지 않는다.

아래 파일은 모두 명시한 고정 커밋에서 직접 읽었다. 아래는 **정적 확인**이며 빌드·테스트 실행·실기기 성능 확인 결과가 아니다.

### 7.2 독립 기술 대안과 새 구성(제안, 아직 작성하지 않음)

| 기술 대안 | 적합한 점 | 절충과 선택 |
|---|---|---|
| B1. TypeScript Web + 의미론적 HTML/CSS UI + Web Audio/Worker | 설치 없는 iPhone Safari 진입, 브라우저 입력/PCM/Worker 계약을 한 언어로 추적, 소규모 화면의 기본 접근성·테스트 경계 단순 | Safari 입력 처리/중단/로컬 모델 자원 제한이 핵심 위험. **설계자의 우선 검증안**이며 T02/T03 실패 전제로 탈출 경로 유지 |
| B2. Flutter Web 유지 | 기존 UI/테스트·Dart 경험이 실제로 있으면 비용 절감 가능 | 새 훈련에는 기존 화면의 직접 가치가 적고 Dart↔JS PCM/Worker 인터페이스 관리가 추가됨. 기존 코드가 있다는 이유만으로 기본 선정하지 않음 |
| B3. iOS/크로스플랫폼 네이티브 | 오디오 세션·파일/모델 실행 통제를 더 직접 다룰 가능성 | 설치/배포·별도 플랫폼 기술·기기 유지비 추가. 네이티브도 음압/발음 정확성을 자동 보장하지 않음. Safari 핵심 경로가 성립하지 않을 때 사용자에게 플랫폼 변경과 비용을 다시 제시 |

현재 권고는 **B1으로 입력·발음 가능성을 먼저 검사하고**, 적합하면 같은 기술로 작은 독립 제품을 만드는 것이다. TypeScript/번들러의 구체 버전은 구현 착수 시 공식 문서·현재 보안/호환성을 확인해 잠근다. 장기 운영·복잡한 편집 화면이 없는 초기 단계이므로 UI 프레임워크는 필수로 도입하지 않는다. 이후 필요가 생기면 채택 이유·추가 의존성·접근성/번들 비용을 별도 결정 기록에 남긴다.

```text
새 제품 Web UI: Home / Prompt / Capture / Feedback / Comparison
  └─ TrainingSessionController (시도·기준·보류·취소, 모듈 하나)
      ├─ PromptCatalog (검수·허용변이·콘텐츠 버전)
      ├─ ReferenceStore / AttemptStore (기본 메모리, 명시 저장만)
      └─ TrainingAudioPort v1 (브라우저 독립 도메인 계약)
          └─ Browser CaptureSession (epoch·입력 fingerprint·bounded PCM)
              ├─ Quality/VAD helper (독립 평가한 후보)
              ├─ RelativeLevelAnalyzer
              ├─ PitchAnalyzer Worker (후보 검증 후)
              └─ PronunciationAdapter Worker (P0~P3 통과 후)
```

- 새 구성의 파일 경계 제안: `src/domain`(상태/결과 계약), `src/audio`(캡처/리샘플/품질), `src/workers`(분석), `src/content`(검수 콘텐츠), `src/ui`(접근성 화면), `tests/fixtures`(합성·동의된 비식별 시험자료). **경로를 만들거나 제품코드를 작성한 것은 아니다.** 최종 저장소도 아직 정하지 않았다.
- 기존 앱과 새 제품의 진입점·저장소/배포는 분리한다. 기존 등록 가이드의 보류된 수정과 섞지 않는다. 기존 자산을 채택할 때는 새 요구·신호경로·라이선스·지원 조건에 맞는 단위만 별도 결정/회귀 시험한다.
- `PronunciationAdapter`는 엔진별 PCM 요구율·phone inventory·가능한 대비·버전·조건을 명시한다. 예상 결과를 반환하는 fake는 테스트 fixture에만 있고 실제 엔진인 척 UI에 표시하지 않는다.
- Browser input→필요 표본율 리샘플은 Worker에서 명시, 원래 표본율/방법/버전 보존. 기존 speaker용 1초 리샘플러가 발음/피치에 적합하다고 가정하지 않고 대역·경계·aliasing을 시험한다.
- 모델은 동일 출처의 버전/해시 고정 자산을 기본으로 한다. 다운로드와 오디오 업로드는 별개다. 동시 여러 분석 모델·화자모델을 기본 로드하지 않는다.
- 발화 8초+앞 250ms/뒤 350ms의 최대 8.6초 48kHz float mono PCM은 약 1.65MB/시도다(모델·복사본 별도). 최대 A/B 두 시도만 유지하는 상한과 Worker transfer를 설계하며, Safari 실기기에서 메모리·발열·종료를 실제 검사한다. 지원을 특정 메모리 API 수치만으로 판정하지 않는다.
- 고정 PCM은 분석 Worker가 소유하며 UI/AttemptStore에는 handle·파생결과만 전달한다. 선택 재청취는 그 handle로 일시 재생 버퍼를 요청하고 완료/취소 뒤 해제한다. A/B 두 고정 시도 상한을 넘으면 사용자 선택에 따라 이전 미저장 시도를 폐기한다. 분석 오류/취소 시 해당 PCM handle도 무효화한다.
- 첫 방문은 HTTPS·앱/모델 자산 다운로드가 필요하다. 캐시가 없거나 모델이 손상되면 오프라인 분석을 보장하지 않으며 불가를 표시한다. 모델/콘텐츠가 준비된 뒤의 분석은 로컬 경로로 시험한다. PWA/오프라인 설치는 초기 필수가 아니다.

### 7.3 인터페이스 계약

설계 수준 계약이며 실행 코드가 아니다.

| 동작 | 입력 / 출력 | 불변 조건 |
|---|---|---|
| `prepare(module, promptId, options)` | engine capability, actual input settings, ready/error | 사용자 클릭 안에서 context resume; 마이크 켜짐 표시; 아직 녹음 저장 안 함 |
| `beginAttempt(referenceId?)` | attemptId, epoch | 명시 사용자 클릭→재준비→actual settings/동일 경로 확인. 조건 다르면 이전 기준 비교 금지. 준비 30초 만료, 버퍼 상한 설정 |
| `finishAttempt()` | finalizing→captureReleased→analysis progress→ModuleResult | post-roll≤350ms·전체 PCM≤8.6초. track/node/timer 해제 확인 후 분석, 신규 샘플 0; 고정 PCM 소유권만 Worker로 이동 |
| `cancelAttempt(reason)` / `stop()` | release acknowledgement | track/node/timer/PCM/Worker 작업 정리; 늦은 응답 폐기 |
| `analyze(buffer, prompt, settings, signal)` | `ModuleResult` | raw PCM은 Worker 내부 소유; 외부 네트워크 전송 없음이 기본 |
| `compare(a,b)` | `comparable` 또는 이유 + 비교 | 동일 prompt/reference/input/engine/pipeline; 조건 다르면 개선 판정 금지 |
| `saveSelection(selection, consent)` / `delete(scope)` | 저장 범위/삭제 결과 | 원음과 수치 선택 별도, 저장·삭제 테스트 가능 |

### 7.4 최소 데이터 스키마

```text
PromptSpec { id, contentVersion, writtenText, acceptedPronunciations[],
  supportedContrasts[], targetVisual, cueIds[], cueSource, reviewerStatus }
InputContext { sessionId, epoch, settingsRevision, sampleRate, channels,
  requestedProcessing, actualProcessing: true|false|unknown,
  signalPath, pipelineVersion, ephemeralRouteToken, placementConfirmed }
Reference { id, module, promptId, inputFingerprint, createdAt,
  provenance: self_reference|listener_agreed, stats, engineVersion }
Attempt { id, module, promptId, referenceId?, inputFingerprint,
  startSample, endSample, qualityFlags[], engineVersion, analysisVersion }
ModuleResult { attemptId, status: valid|limited|abstain|error, reasonCodes[],
  supportedScope, measurement?, comparisonCandidates?, uncertaintyLabel,
  displayCueId?, limitations[], modelVersion?, thresholdVersion }
LevelMeasurement { intervalStart, intervalEnd, sampleCount, integratedDbfs,
  frameSpread, relativeDb?, durationMs, speechOccupancyEstimate,
  backgroundEstimate, comparisonEligibility, rejectedReason? }
PitchMeasurement { voicedIntervals[], abstainedIntervals[], relativeSemitones[],
  coverage, startWindow?, endWindow?, startEndDeltaSemitones?,
  directionScope: first_last_voiced_window, direction? }
PronunciationComparison { segments: [{range, contrastId,
  result: target_like|contrast_candidate|abstain, candidate?, reasonCodes[]}],
  supportedCoverage, calibrationVersion, scopeEligibilityVersion, decisionPolicyVersion }
SavedSelection { schemaVersion, savedAt, selectedAttemptIds[],
  includeAudio: false(default), storageScope: local, consentVersion }
```

`inputFingerprint`는 내부 조건 비교용이며 영구 장치식별자가 아니다. 페이지 내에서만 같은 reported deviceId 여부로 입력경로 토큰을 유지하고 외부/지속저장에는 식별자를 넣지 않는다. 재준비 때 경로 식별이 없거나 달라졌으면 비교를 보류한다. 설정이 같아도 숨은 장치처리/거리 변화까지 보장하지 않는다. 새로고침 뒤 저장된 과거 기준은 읽기용 기록이며 새 세션의 목표 비교에는 새 기준이 필요하다. 발음 후보·전사도 민감 정보로 취급한다. 내부 posterior/점수는 별도 동의된 연구 데이터에서만 보존하며 일반 사용 기록에는 넣지 않는다. 스키마 버전 불일치/오래된 기준은 읽기 오류 대신 재기준을 안내한다.

## 8. 개인정보, 저장·삭제, 외부 모델과 권리

- 정상 완료/시간 한도/post-roll 뒤 마이크·노드를 해제하고 분석/결과에서는 새 소리를 수집하지 않는다. 준비만 하고 30초 안에 시작하지 않으면 자동 중지한다. 결과 화면 장기 체류·분석 지연/실패도 수집을 연장하지 않는다. 재시도는 새 클릭/실제 설정 확인을 거친다.
- 기본: 로그인·서버·분석 SDK 없음. 원음/기준/후보/전후 결과는 브라우저 메모리에만 둔다. 종료·취소·초기화 시 버퍼/참조 해제; JavaScript의 완전한 물리적 메모리 영구 삭제까지 보장한다고 말하지 않는다.
- 저장은 결과 화면에서 사용자가 선택한 시도만. 기본은 수치·기준 저장, **원음 저장은 별도 선택**. 로컬 브라우저 저장도 같은 기기 사용자/브라우저 삭제/백업의 한계가 있고 서버 백업은 없음을 알린다.
- 저장목록에서 항목별/전체 삭제·기준 초기화 제공. 브라우저 데이터 삭제 시 복구 불가 안내. 다운로드한 파일·사용자가 공유한 복사본은 앱이 회수/삭제할 수 없음을 고지한다.
- 학습·연구 제공은 앱 사용 동의와 분리한다. 수집 목적/대상 항목/보관 기간/접근자/철회 방법/평가셋 재사용 여부를 연구 시작 전에 확정한다. 장애 관련 정보는 결과 분석에 필요한 최소 선택 항목만 수집하고 공개 저장소에 넣지 않는다.
- 외부 엔진이 필요한 경우: 제공자·보낼 원음/텍스트·전송국가·저장/모델학습 사용·보존/삭제·비용·대체 경로를 먼저 확인한 뒤 **특정 외부 전송에 대한 명시 동의와 사용자 승인**을 받는다. 동의하지 않으면 해당 자동분석이 불가할 수 있음을 솔직히 알리며 무단 업로드하지 않는다.
- 네트워크 시험으로 원음/전사/후보가 외부 요청·오류 로그·analytics에 섞이지 않는지 확인한다. 자산 다운로드 실패가 서버 음성 업로드로 자동 전환되는 fallback을 만들지 않는다.
- 키/토큰은 클라이언트·GitHub·설계 문서에 넣지 않는다. 모델·런타임·콘텐츠·데이터의 허가를 분리한 자산 manifest(출처, 버전, hash, 라이선스, 수정, attribution, 허용범위)로 관리한다.
- 바름의 화면·음성·문구·코드·모델 복제나 API 접근을 가정하지 않는다. 공개 발표에서 확인한 동작 원리를 참고해 독립 설계한다. 기존 RNNoise/libfvad/WeSpeaker notices는 변경 없이 보존하고, 사용하지 않는 화자 자산의 배포 제외 여부도 새 빌드 검토에 포함한다.

## 9. 검증 계획과 사전 결정 규칙

### 9.1 검증의 세 층

1. **기술 측정**: 입력·상대 음량·F0·지원 음소 비교가 정해진 조건에서 맞는가.
2. **실제 효용**: 당사자가 피드백을 이해하고 자율 연습에 쓰며 기존 방법보다 도움을 얻는가. 기술 정확도만으로 통과하지 않는다.
3. **장기 효과/일상 전이**: 연습 이후 낯선 문장·청자·생활 상황의 의사소통이 나아지는가. 단회 전후나 모델 점수로 주장하지 않는다. 별도 장기 연구 전에는 미입증으로 남긴다.

아래 숫자는 **팀이 제안한 연구·공학 통과 기준 초안이지 임상 기준·기존 연구에서 검증된 기준이 아니다.** 최종 모집 가능성·오류 비용을 당사자/전문가와 검토하여 시험 전에 확정·버전 잠금한다. 결과를 본 뒤 통과시키기 위해 낮추지 않는다. 표본 부족·신뢰구간이 넓으면 ‘미결정’이며 통과가 아니다.

### 9.3 발음 평가셋의 최소 운영 설계

- 모델 후보 탐색·임계값 보정·잠금 평가의 화자를 분리하고 동일 사람의 다른 녹음이 섞이지 않게 한다. 단어/문맥도 일부 별도 holdout으로 일반화 범위를 표시한다.
- 초기 운영 제안은 calibration 8–12명 + 잠금 평가 **별도 12명 이상**이다. 이는 충분한 통계 검정력을 보장하는 표본수가 아니다. 모집/전문가 확보 전에는 가능하다고 확정하지 않는다.
- 오지적/precision 신뢰구간을 계산할 만큼 판정 가능한 실제 사례가 필요하다. 시작 예산은 잠금셋에서 대비별 정답/허용 구간 100개 이상·독립 라벨의 실제 대비 오류 구간 100개 이상을 초기 표본계획 검토의 출발점으로 두되, 같은 사람의 반복 구간을 독립 100명처럼 세지 않는다. 두 앱 출력의 precision과 거짓수용 구간까지 만족하는 데 이 수가 충분하다는 보장은 없으며 신뢰구간/군집을 반영해 사전에 표본계획을 확정한다. 실제 오류가 희소하면 오류를 억지로 유발해 자연환경 precision으로 보고하지 않는다.
- 참가자 군집을 고려한 재표집/구간 추정과 사람별 결과를 함께 제시한다. 자연 발화 분포 셋과 의도적으로 오류를 모은 challenge 셋의 결과를 분리하고, 자연환경 precision은 자연셋에서만 판단한다.
- 라벨러 일치도가 낮거나 음소 경계를 신뢰하기 어려우면 정답셋 자체가 불안정하다. 독립 라벨·불일치·합의/제외 사유를 공개하고, 그 상황에서 성능 수치를 확정하지 않는다.
- 재활사·당사자·평가자 모집은 아직 확약이 없다. 확보 실패는 제품 개발 일정의 핵심 blocker다. 개인 녹음·장애정보·동의서·원문 전사는 GitHub에 올리지 않는다.

### 9.4 오류 비용과 중단

- 잘못된 발음 지적으로 인한 좌절/불필요한 교정, 잘못된 ‘적절함’ 판정, 큰/높은 소리를 무리하게 내게 만드는 피드백을 단순 불편보다 높게 취급한다.
- 평가 중 통증·심한 불편/좌절·개인정보 사고·동의 없는 녹음/전송 발생 시 해당 세션 즉시 중지하고 피드백 기능을 잠근다. 실제 조사에서는 대응·연락·철회 담당을 사전 지정한다.
- 실패 후 고칠 수 있는 것은 입력/콘텐츠/엔진/UX다. 수요가 없거나 안전하고 유용한 피드백을 만들 수 없다는 결과는 프로젝트 중단 근거가 될 수 있다.

### 9.5 T07 가까운 대안과 자율 다음행동의 추가 효용

**비교 대상 선정 규칙**

1. 시험 직전 실제 접근 가능한 후보를 공식 자료로 확인하고 지원언어·기기·비용·허가·입력/개인 기준·피드백·재시도 흐름을 기록한다. 필요한 구매·설치·외부 서비스 사용은 별도 승인 전 실행하지 않는다.
2. 음량/높낮이의 우선 가까운 대안은 **Voice Trainer 같은 개인 기준+음량/피치 피드백을 가진 실제 훈련 도구**다. 일반 dB/pitch 그래프만을 주 비교로 삼아 상대를 약하게 만들지 않는다. 발음은 현재 접근 가능한 한국어 시각 발음비교 도구를 조사하며, 바름은 현행 접근/허가를 확인하기 전 실제 사용 비교가 가능한 제품으로 가정하지 않는다.
3. 기기·언어·허가·설정 지원 때문에 실제 앱 비교가 불가능하면 이유를 남기고, 그 핵심 능력(개인 기준/품질 안내/시각 피드백/재시도)을 합법적으로 맞춘 비교 조건을 설계한다. 이름만 붙인 빈 그래프가 아니다. 이 경우 결과는 **능력을 맞춘 조건 대비**이며 실제 경쟁 제품보다 우수하다는 증거로 홍보하지 않는다.
4. 참가자가 쓰던 dB 앱/녹음·전사·도우미 방법도 별도 기준이다. STT나 재생만 있는 조건이 발음 자동피드백과 동등한 대안이라고 주장하지 않는다. 도우미 조건은 도움 시간/비용도 기록하되 이를 숨겨서 무조건 자율앱이 우세하도록 만들지 않는다.

| K3 다음 한 조절 | 도움 없이 자기 목표에 맞는 한 행동 선택·실행 | 크기=목표 방향과 입력조건 유지; 발음=검증 후보에 연결된 검수 교육 단서 하나 선택; 높낮이=처음/마지막 유성창 차이 목표와 일치. 적절한 선택지는 전문가/당사자 검토로 사전 정의 | 단서 선택 못함·연구자 도움·원인 미확인인데 무조건 크게/높게·지원 밖 교정 |
| K4 결과 확인 | B의 관찰 결과를 보고 ‘원하는 변화/아직 아님/판단불가’를 구분 | 기술/독립 참조에 맞게 A/B 변화 또는 보류를 해석. 발음은 후보/라벨·검수 단서 범위 안에서, **재청취 없이** 수행 가능해야 함 | 화면을 끝까지 눌렀지만 결과를 오해하거나 소리 재생/타인 설명 없이는 피드백을 해석 못함 |

- `자율 유효행동 성공`은 한 과업의 K1~K4를 모두 연구자 도움 없이 충족한 경우다. 버튼 완료율·호감·재사용 선호와 별도 집계한다. 임상적으로 소리가 개선돼야 한다는 단회 치료시험은 아니며, 원한 변화가 안 생겼음을 정확히 파악하고 멈추는 것도 K4의 적절한 행동이다. 원하는 **실제 음향/지원 대비 변화가 생긴 비율**도 별도 측정해 해석만 잘하는 앱인지 구별한다.
- 제안하는 절대 기준은 범위/보류 의미 이해≥80%, 전체 자율 유효행동 성공≥70%, 비교불가 과업에서 무효 개선판정/유해 행동 0건이다. 기존 r1의 80%/70% 기준을 더 강한 행동 정의에 적용하며 단순 완료로 낮추지 않는다. 절반 이상의 구체적 재사용 이유는 수요 보조자료일 뿐 이것만으로 통과하지 않는다.
- 추가효용의 초기 기준은 **가장 가까운 대안 대비 자율 유효행동 성공률 +20%p 이상**, 대응비교의 사람 단위 95% 신뢰구간 하한>0, 위험한 오해/오행동 증가 없음이다. 준비·설정/피로 부담이 증가하면 그 비용을 함께 판단한다. 소규모 8–12명은 문제 발견용 탐색 시작표본이며 이 비교를 확정할 검정력 보장이 아니다. 비교 표본계획을 사전 확정하고 부족하면 미결정으로 남긴다.
- 관찰 가능한 목표 변화는 방향·지원 대비 범위의 기술 결과로만 보고한다. 가까운 대안보다 변화 달성이 나쁘면서 유효행동만 좋아지면 이 trade-off를 숨기지 않고 제품화 보류/재설계한다. 효용 차이가 없거나 부담이 더 크면 세 메뉴를 합친 편의만으로 정당화하지 않는다. 기능별 근거가 다르면 차이를 공개하고 사용자의 범위 재승인 없이 모듈을 삭제하지 않는다. 장기 일반화/청자 소통효과는 T11 미검증으로 남는다.

고정 납기·인원은 현재 요청에서 재확정되지 않았다. 아래는 **완료 조건 순서**이며 ‘초보팀 3주면 완성’ 같은 일정을 약속하지 않는다.

|---|---|---|
| G0 설계·근거·교수 검토 | 이 문서, 비판/수정표, 잔여 가정과 사용자 승인 | **지금 가능:** read-only 조사·문서. **금지:** 제품코드/스캐폴딩/설치/배포 |

| G3 선택형 통합 프로토타입 | 1항목 흐름·A/B·보류·취소·로컬 데이터, T08/T09 | 지원 조건 통과한 모듈만 연구 참여자에게 제공. 일반 공개·효과 홍보 금지 |

각 게이트 보고에는 `통과 / 실패 / 표본·자료 부족으로 미결정` 중 하나와 근거 파일을 남긴다. 교수 검토는 미결정을 통과로 바꾸지 않는다. 구현 시작 후에는 별도 작업계획·TDD/회귀·코드검토·검증 절차를 적용한다.
