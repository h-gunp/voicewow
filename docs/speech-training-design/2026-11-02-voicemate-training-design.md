## 0. 한 페이지 요약

사용자가 원하는 한 항목을 골라 짧게 연습하거나 학습하고 종료한다. 세 항목 강제 완주·종합 발음 점수는 없다.

| 항목 | 핵심 흐름 | 피드백의 정확한 의미 | 주장하지 않는 것 |
|---|---|---|---|
| 목소리 크기 | 상황 참고선 선택 → 마이크/고정 배치 확인 → 짧게 말하기 → 현재 입력 보기 → 원하면 같은 조건에서 재시도 | 기존 VoiceMate의 디지털 참고척도와 선, 별도로 정의한 A/B 상대 입력 변화 | 절대 SPL/dBA·보편적 적정 음량·치료 효과 |
| 발음 지식 퀴즈 | 목표 단어/규칙 읽기 → 발음 표기 선택 → 문항 정답·이유 확인 → 새 예제/복습 | **문항에 대한 선택과 지식/규칙 이해**. 마이크 불필요 | 사용자의 실제 발음 정확성·음소 오류 진단·발화 향상 |
| 높낮이 | 자기 유성 발화의 F0 보기 → 원하는 변화 탐색 → 처음/마지막 유성 창 차이 비교 | 지원 조건에서의 상대 F0 추정. 기준은 새로 합의할 필요가 있음 | 기존에 검증된 피치 정답·정상 피치·억양 적절성 |

현재 가장 중요한 불확실성은 (1) 퀴즈가 당사자가 원하는 학습인지, (2) 기존 디지털 음량 참고선을 새 앱에서 사용자가 적절성 보증으로 오해하지 않는지, (3) 배치·iPhone 입력 조건을 유지할 수 있는지, (4) 가장 가까운 기존 대안보다 추가 도움이 있는지다. 자동 음소분석 엔진 확보는 **현재 제품의 필수 게이트가 아니다**.

진행 순서: 변경 설계 재검토 → 사용자 승인/피치 범위 확인 → 콘텐츠·입력 기술 검증 → 작은 통합 시제품 → 당사자 비교시험 → 제품화 판단. 언어재활 접근 장벽이 있다는 자료가 나와도 이 앱이 치료를 대체하거나 비용 문제를 해결한다는 결론은 별도로 입증해야 한다.

## 1. 대상·목적·비목표

### 1.1 초기 대상과 사용 순간

- 한국어 구어를 사용하며 **본인이** 크기/높낮이 변화 확인 또는 발음 지식 학습을 원하는 성인 청각장애인·난청인.
- 기관 밖에서 짧게 하는 선택형 학습/연습을 가설로 둔다. 듣기 능력·청력 손실 시점·보장구·구어 경험은 다양하며 장애명만으로 같은 요구를 가정하지 않는다.
- 퀴즈는 한국어 표기와 발음 표기의 차이를 읽어 이해할 수 있는지 초기 사용성 확인이 필요하다. 단순히 한국어를 읽는다고 발음 표기까지 쉬운 것은 아니다.
- 수어·필담을 대체하거나 구어/표준어 사용을 강요하지 않는다. 발음 규칙을 자발적으로 배우는 기능이며 사람의 말하기 방식을 정상/비정상으로 분류하지 않는다.

### 1.2 결과 수준을 구분한다

1. **작동**: 퀴즈 채점이 문항 기준과 일치하고, 마이크/F0/음량 경로가 정의대로 동작한다.
2. **이해·자율 사용**: 결과를 올바르게 설명하고, 비교 불가일 때 멈추며, 필요한 다음 학습/조절을 스스로 선택한다.
3. **지식 학습**: 처음 보는 동등 난이도 예제에 규칙을 적용하거나 일정 기간 뒤 기억한다.
4. **발화/생활 효과**: 실제 발음·낯선 청자 이해·일상 의사소통이 좋아진다.

1~3이 성공해도 4가 입증된 것이 아니다. 퀴즈 정답률을 실제 발음 정확도나 재활 효과로 표시하지 않는다.

### 1.3 비목표와 금지되는 오해

- 치료·진단·재활사 대체, 장애 평가, 안전 음압 검사, 언어재활 접근 비용의 해소 보장.
- 사용자 음성의 자동 음소분석/발음 정오·조음 처방·바름 엔진/API 사용. STT 기반 진단도 넣지 않는다.
- 퀴즈 오답을 ‘당신이 잘못 발음하는 음소’로 기록하거나, 퀴즈 100점을 ‘발음 100점’으로 바꾸는 것.
- 절대 dB 정답·성별 정상 피치·사투리 오류·통합 성적·순위·강제 출석·무리한 큰/높은 소리 유도.
- 다자 실시간 대화·상시녹음·자동 본인 화자 분리·청취/전화 보조.
- 단순 호감·버튼 완료·문항 암기만으로 추가 가치나 일반화 효과를 주장하는 것.

불편·피로·통증·좌절 시 즉시 종료할 수 있다. 지속적인 발성 불편을 앱이 진단하지 않고 전문가 상담을 안내한다.

### 2.3 언어재활의 거리·비용 장벽: 확인 범위와 제품 가설

**장벽의 존재를 뒷받침하는 자료는 있으나, 현재 한국 청각장애·난청 성인의 장벽 빈도/규모를 직접 추정할 대표 자료는 이번 조사에서 확인하지 못했다.** [조사 부록](rehabilitation-access-evidence.md)의 대상·연도·출처·한계를 보존한다.

### 3.2 새 앱의 적용 계약 — 숫자 복사와 정당화는 다르다

- 사용자의 기존 기준 요청을 반영하여 크기 연습의 현재 입력 화면에 **quiet 53–75 / meeting 68–78**의 참고선을 제안한다. 이유는 사용자 선호·기존 경험의 연속성이지 자문에서 적정 수치가 검증됐기 때문이 아니다.
- 척도 이름은 ‘기존 VoiceMate 참고 입력 수준’. dB SPL/dBA, 안전/정상/적정 범위라는 이름을 쓰지 않는다. ‘참고선 아래/안/위’는 숫자의 위치 설명일 뿐이다. 범위 안 체류율을 발화 실력·사회적 적절성 점수로 만들지 않는다.
- 이 선을 적용할 현재값은 **기존과 같은 RNNoise 처리 frame RMS→meterDbfs→+114→clamp** 경로에 한정한다. 원본 입력 RMS, whole-attempt 평균, 다른 소음억제 엔진, F0, 퀴즈 정답률에 그대로 붙이지 않는다. 경로가 달라지면 같은 숫자라고 가정하지 않고 재검증한다.
- 현재 코드의 환경 적응은 실제 처리 설정 셋이 false이고 analysis ready, 유한 offset 0..3일 때 상·하한을 함께 이동한다. r3의 짧은 고정 연습은 **기준이 움직이는 혼란을 피하려고 기본 고정선**을 제안한다. 환경 적응을 새 훈련에 자동 이식하지 않는다. 기존 적응까지 동일하게 원하는지 별도 범위 결정이 필요하다.
- 과거 기준값의 의학적/사회적 타당성을 지금 새로 입증했다고 말하지 않는다. T02/T05가 통과하기 전에는 공개 목표 훈련으로 제공하지 않으며, T07에서 오해가 계속되면 참고선 UI를 수정한다. ‘기존 앱에 있었다’는 이유로 검증을 면제하지 않는다.
- A/B 비교는 별도의 **전체 구간 원본 입력 에너지 차이**로 정의한다(§6.1). 이 결과에 53–75 등을 붙이거나 현재 처리 frame 수치와 직접 비교하지 않는다. 한 화면에 두 척도를 섞지 않고 현재 입력→완료 후 A/B의 단계로 분리하며 의미를 설명한다.

### 3.3 높낮이의 미확정과 책상 위 배치 확정

- 현재 읽은 설정·상태·화면·음성처리 코드와 `pitch/F0` 검색에서 **상속할 높낮이 목표 Hz/반음 범위를 확인하지 못했다**. 검색 무결과를 저장소 전체 부재의 증명으로 과장하지 않는다. 적어도 확인된 ‘기존 VoiceMate 피치 기준’은 없다.
- 따라서 성별 정상치나 임의 Hz를 기존 기준이라고 만들어 넣지 않는다. 현재 제안은 개인 상대 F0 시각화이며, 피치 목표 범위/처음-마지막 비교를 원하는지 사용자 확인(Q02)이 필요하다.
- 배치(Q01)는 사용자 최종 정정으로 **앞쪽 책상 위**다. 안내문: **‘휴대폰을 앞쪽 책상 위에 놓고, 연습하는 동안 위치와 방향을 유지해 주세요.’** 같은 문구를 준비 화면·배치 그림·시도 조건·재기준 안내·시험에 사용한다. 책상 높이·입과의 거리·마이크 방향·물체 차폐를 실제 시험에 기록한다. 휴대전화를 옮기거나 방향을 바꾸면 비교를 보류하고 재기준한다. 책상 위라는 요청된 위치도 정확성/적정 음압의 증거는 아니다. ‘책상 아래’는 철회된 표현이며 미결정으로 남기지 않는다.

## 5. UX·상태·실패와 복구

### 5.1 홈과 두 종류의 학습 흐름

**홈**은 세 항목 이름과 서로 다른 결과 의미를 먼저 보여준다. ‘발음 지식 퀴즈—내 목소리는 평가하지 않음’을 명시한다. 마이크를 열기 전에 사용자가 항목을 선택한다.

**크기/높낮이**: 항목→목표/상황 선택→배치/척도 의미 확인→마이크 준비→짧은 발화 A→완료·마이크 해제→시각 결과/보류→원하면 한 조절 후 B→조건이 같을 때만 비교→종료/명시 저장.

**발음 지식 퀴즈**: 주제/짧은 문항 선택→단어/문맥·보기 읽기→선택/모르겠음/건너뛰기→제출→문항 정답과 짧은 이유/출처→원하면 새 예제/나중에 복습→종료. 마이크 허용·발화·녹음·재생이 없어도 완결된다.

- 같은 생활 소재로 연결할 수 있지만 모든 퀴즈를 음량 발화와 묶지 않는다. 퀴즈 완료를 발화 숙련으로 처리하지 않는다.
- 점수는 ‘처음 푼 문항 정답 3/5’처럼 **문항 지식**에 한정한다. 재시도 정답과 첫 답을 분리한다. 헷갈린 문항/규칙을 다시 보는 선택은 있어도 ‘당신이 잘못 발음하는 자음’ 통계는 없다.
- 정답/오답·건너뛰기 후에도 자동 다음 이동을 강요하지 않는다. 설명을 읽는 시간, 종료, 글자 확대를 허용한다.

## 6. 세 모듈의 상세 계약

### 6.0 공통 오디오·품질

원본은 브라우저가 전달한 PCM이며 하드웨어 이전의 원시 음압이 아니다. requested processing과 actual settings(true/false/unknown), sampleRate·경로·pipelineVersion을 기록한다. false 설정도 숨은 처리 부재를 보증하지 않는다.

- ①브라우저 PCM/고정 발화 버퍼와 ②RNNoise+VAD/기존 현재 막대 경로를 명확히 나눈다. 처리 전후 값을 같은 척도라고 섞지 않는다.
- `sessionId/epoch/settingsRevision/sampleStart/sampleEnd`로 순서·공백·묵음·중복/지연을 검증하고 stale/NaN/clip/불확실에 과거 정상값을 유지하지 않는다.
- VAD는 화자 식별·발음 정확성·청자 이해가 아니다. 혼자 연습을 기본으로 하며 타인/TV가 섞이면 중지/재녹음을 안내한다. 혼입 자동 검출 보장 없음.
- audio 결과는 valid/limited/abstain/error. 보류를 0점/사용자 실패로 표시하지 않는다. quiz의 correct/incorrect/skipped와 다른 도메인이다.
- 정상 완료/시간 한도/post-roll 뒤 캡처 해제, 분석/결과 수집 0, 재시도 재준비를 적용한다(§5.2). 퀴즈는 이 캡처 계층을 사용하지 않는다.

### 6.1 목소리 크기

**A. 현재 입력과 기존 참고선**

- §3의 현 UI 두 모드와 같은 경로의 `legacyLevel=clamp(20log10(processedFrameRms)+114,0,120)`를 사용한다. 상·하한은 quiet 53/75, meeting 68/78. 유효 신선 발화가 아니면 `—`와 이유를 보여준다.
- RNNoise/VAD의 작은 프레임 누락이 있으므로 **유효 frame만 모아 문장 평균/중앙값·범위 안 비율·훈련 점수를 계산하지 않는다**. 현재 frame 표시와 문장 전체 대표값은 다른 개념이다. 표시가 비었던 시간을 연습 성공에서 숨기지 않는다.
- 프레임이 30ms 연속 발화로 판정되었다는 것은 실제 대상의 발화 시작·무성 자음 검출이 검증됐다는 뜻이 아니다. 초기 실패/unsupported rate/오류에는 참고선 목표 피드백을 보류한다. 원본 fallback에 같은 +114 참고 목표를 붙여 조용히 계속하지 않는다.
- ‘참고 범위 안’은 숫자 위치이며 건강/상황 적절성 보증이 아니다. 이를 이용자가 이해하는지 T07에서 확인한다.

**B. A/B 상대 변화 — 전체 구간을 보존**

- 같은 짧은 말·기기·배치·경로에서 사용자가 누른 발화 시작~완료 구간의 모든 유한 표본으로 `L=10log10(sum(x²)/N)`를 계산한다. 앞/뒤 여유 버퍼는 제외한다. **낮은 에너지나 VAD 비발화라는 이유로 표본을 빼지 않는다.** 작은 프레임 탈락으로 실제 감소가 가짜 증가가 되는 문제를 차단한다.
- `ΔL=L_B−L_A`는 그 구간의 디지털 입력 에너지 차이로, 침묵·잔여 잡음도 포함한다. 53–75/68–78의 참고선을 이 전체 구간 값에 붙이지 않는다.
- NaN/공백/clip/일부 발화 손실은 전체 시도 보류. 초기 비교 조건은 같은 내용·길이 차≤10%·VAD 보조 발화 점유 차≤10%p, 준비/마무리 비발화 후보 각 ≤250ms의 배경 변화≤3dB·집계/배경 에너지 비≥10dB다. 모두 검증 전 팀의 시작값이며 진짜 SNR/음성 분리를 보증하지 않는다.
- 조건 변화/배경 불안정·작은 신호가 품질 gate에 막힌 표본도 평가 분모에 남긴다. VAD가 작은 발화를 놓친다면 ‘정확한 변화를 측정했다’가 아니라 그 경로의 coverage 실패다.
- AGC true/unknown은 원칙적으로 A/B 목표 비교 보류. 별도 잠금 평가한 특정 경로만 예외 지원 가능하다. 값 false·사용자의 위치 확인만으로 조건 동일성을 보증하지 않는다.

**T05 기술 gate와 반례**

- 같은 실제 발화 파형에 ±3/6dB gain, 고정 잡음+음성만 gain, 전체 gain, 약한 음절/부분 소실, clipping, AGC 압축을 넣어 **VAD/품질/집계 전체 경로**를 시험한다. 알려진 전체 gain의 디지털 오차≤1dB·방향 일치≥95%를 시작 기준으로 둔다.
- 실기기는 독립 고정 참조 레코더의 상대 응답(AGC/limiter 없음)을 먼저 확인하고 같은 구간 `Δ_ref`를 동기 측정한다. 재생기 명령값만 실제 소리 정답으로 쓰지 않는다. 절대 SPL 정확도를 보증하는 시험이 아니다.
- `|Δ_ref|≥3dB` 적격 paired trial 전체(앱 보류/오류 포함)에서 같은 부호 `|Δ_app|>1dB`가 방향 정답, ±1dB 내는 판별 어려움, 반대 부호>1dB는 역방향 오안내. 경로별 방향≥95%(95% 하한≥90%), 역방향 0건(95% 상한≤5%), A/B coverage≥80%, 유효 출력 절대차 오차 중앙값≤2dB를 **동시** 요구한다. 사람/세션 군집·표본 부족을 고려해 시험 전 방법을 잠근다.
- 추가로 현재 막대/기존 참고선 경로의 작은 발화/VAD 거절·소음 오탐·표시 공백을 별도 보고한다. A/B gate 통과가 기존 선의 적정성 입증이 아니다. 숫자/단위 오해는 T07의 별도 차단 조건이다.
- `[.01,.01,.01,.10]`을 절반으로 줄인 경우 전체 에너지는 −6.021dB다. `.007` 미만을 빼고 선택 중앙값을 쓰면 +13.979dB로 뒤집힐 수 있다. r3도 선택 집계를 금지한다. 거리 변경/일부 소실/AGC 압축을 목표 도달로 통과시키지 않는다.

### 6.2 발음 지식 퀴즈 — 현재 발음 모듈

**기능 정의**: 문자로 제시한 단어/문맥에서 목표 발음 표기를 선택하고, 왜 그런지 설명·예제를 확인하는 인식/지식 학습이다. **사용자 목소리를 인식·평가하는 기능이 아니다.** 귀로 두 소리를 구별해야만 푸는 청각검사도 아니다.

#### QZ-1. 문항 구성과 한 예제

- 문항 유형: (a) 표기→발음 표기 선택, (b) 규칙/변화가 적용되는 예 선택, (c) 짧은 설명 읽고 새 단어에 적용. 초기 10–20문항/2개 규칙 이하를 제안하며 실제 수·난이도는 검수/당사자 이해 후 확정한다.
- 각 문항에는 단어·필요 문맥·학습 범위(예: 표준 발음의 특정 규칙)·선택지·허용 정답 집합·짧은 이유·출처·검토자/버전을 둔다. 자모 단순 분해나 일반 STT로 답을 만들지 않는다.
- 예시 설계: **‘옷이’의 표준 발음 표기로 알맞은 것은?** 보기 `[오시] / [오디] / [옫이]`, 목표 답 `[오시]`. E12의 제13항 예와 연결해 받침과 뒤 음절의 관계를 짧은 문자/도형으로 설명한다. [오디]를 선택했다면 ‘이 문맥에서는 받침 ㅅ을 대표음 ㄷ으로 바꾸지 않고 뒤 음절의 첫소리로 옮긴다’, [옫이]라면 ‘표기된 글자를 각각 읽는 대신 연음을 적용한 소리 표기를 고른다’는 선택별 해설을 제안한다. 이는 문항 설계 예이지 최종 콘텐츠 검수·배포 완료가 아니다.
- 철자/발음 표기·기호 사용법을 먼저 짧게 안내한다. 필요한 경우 한 소리씩 강조하되 음성 재생 없이도 설명이 완결되도록 한다.
- 실제 발음의 허용 변이가 둘 이상이면 문맥/질문을 바꾸거나 정답 집합을 모두 허용한다. 단일 정답 문항에 두 유효 보기가 있으면 문항을 철회한다. 방언·개인의 말하기 방식을 부정하는 distractor를 만들지 않는다.
- 허용 답 반례 예시: [국립국어원 FAQ](https://www.korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=9036&mn_id=98&pageIndex=25)는 ‘맛있다’의 [마딛따]/[마싣따]를 모두 허용한다. 둘을 나란히 제시하면서 하나만 정답이라고 채점하는 단일 정답 문항은 **검수 실패**다. 별도 예제에서 ‘가능한 표준 발음 표기를 모두 고르세요’로 명확히 하고 `multi_exact` 정책으로 두 선택을 정답 집합에 포함하거나, 두 표기가 모두 가능하다는 설명형 문항으로 바꾼다. 한 발음을 개인의 오류로 기록하지 않는다.

#### QZ-2. 채점과 설명

- 채점은 검수된 `itemVersion+choiceId`와 `acceptedAnswerIds` 및 `answerPolicy`를 대조하는 결정적 규칙이다. `single_any`는 명시된 허용 답 중 하나, `multi_exact`는 선택 집합과 정답 집합의 일치를 요구하며 질문/선택 UI도 그 방식과 일치해야 한다. 기본은 단일 정답 문항이고 복수 선택은 해당 설명을 먼저 표시한다. LLM/외부 STT/API가 실시간 정답·교정문을 생성하지 않는다.
- 정답/오답은 **선택한 문항**에 대한 결과다. ‘이 문항에서 선택한 답을 다시 살펴보세요’, ‘이 규칙의 예는…’라고 표시한다. ‘당신은 ㅅ을 틀리게 발음함’은 생성하지 않는다.
- 모르겠음/건너뛰기·미제출을 음소 오류로 세지 않는다. 첫 답·힌트 사용·반복 답을 구분하고, 복습 정답률을 처음 보는 문제 성취로 부풀리지 않는다.
- ‘헷갈린 문항/규칙’ 목록은 선택 저장할 수 있지만 ‘내 발음 취약 음소’ 통계는 없다. `QuizResult`에는 음소 정확도·발음 confidence·F0·녹음 필드가 없다.
- 오류 제보/출처 변경/복수 정답 발견 시 해당 버전을 격리하고 채점·추천을 중지한다. 이전 오답 기록을 사용자 잘못으로 남기지 않고 ‘문항 수정으로 성적 비교 불가/기록 정정’을 처리한다.

#### QZ-3. 콘텐츠/품질 gate

| 단계 | 필수 증거 | 실패 시 |
|---|---|---|
| C0 출처·권리 | 공개 규범/사전 등 문항별 정확 출처, 확인일·목표/허용 변이·사용/배포권. 설명은 독립 작성하고 제3자 그림/음성은 별도 허가 | 출처/권리 불명 문항 사용 금지 |

| C2 대상 이해/접근성 | 당사자가 발음 표기·문항 목적·보기/설명을 청각 없이 이해하는지 cognitive walkthrough | 읽기/발음 표기가 장벽이면 도형/설명/난이도 수정. 쉬워졌다고 실제 발화 향상 주장 금지 |

출시 후보 문항은 출처/권리/정답/검수 필드 100% 충족, 미해소 복수 정답/사실 오류 0건을 요구한다. 검수 통과는 학습 효과 입증이 아니다. 이 인원/비율은 팀의 제안이며 실제 확보가 필요하다.

#### 현재 제외와 미래 요청

이전 release의 발음 엔진 P0-a~e, 음소 posterior/GOP·forced alignment·`target_like`/오류 후보 혼동표는 **현재 개발의 선행조건에서 제외**한다. 이는 검토를 통과하려고 핵심 요구를 삭제한 것이 아니라, 사용자의 퀴즈화 변경에 따른 별도 범위다. 향후 실제 음성 분석을 다시 요청하면 대상/엔진/권리/독립 라벨·거짓 안심/오지적/coverage/개인정보 게이트를 새 revision으로 재설계한다. 기능을 몰래 다시 넣지 않는다.

### 6.3 높낮이 — 기존 수치 없음, 상대 변화 제안

- 확인된 기존 VoiceMate 피치 목표가 없으므로 새 임의 Hz 범위를 상속 기준처럼 넣지 않는다. Q02 답 전에는 **자기 유성 발화의 상대 F0 탐색**까지만 제안하고 정상/목표 범위 판정은 보류한다.
- 후보 YIN 계열의 구현/라이선스는 미선정이다. 에너지·주기성·음성 가능성·클리핑·신선도 gate를 통과한 유성 구간만 표시한다. 기계 잡음/반주가 주기적이라는 사실은 사용자 F0 표시 근거가 아니다.
- 자기 참고 중앙값 `F0_ref` 대비 `12log2(F0/F0_ref)`의 상대 반음 변화, 필요할 때만 상세 Hz를 표시한다. 성별/장애 유형별 정상치·사투리 오류를 부여하지 않는다.
- 비교를 원할 경우 목표는 **첫/마지막 측정 가능 유성 창의 높이 차**다. 각 연속 150ms 후보 창이 겹치거나 부족/불확실하면 방향 보류. `12log2(medianF0_end/medianF0_start)`와 실제 창 시각을 보존한다. 국소 종결부 상승/하강과 다르므로 ‘끝 올리기 성공’으로 이름 붙이지 않는다.
- 무성/보류 공백을 지우거나 0Hz로 채우지 않는다. 0–100% 시간축은 보기용이고, 강제 DTW로 다른 음절을 맞춰 성공을 만들지 않는다.

**T06 정답·오류 계약**: 독립 평가의 10ms 격자 V(유성/F0 가능)/UV(무성·숨·비음성)/U(불확실)를 둔다. 합성 정답과 실제 대상 발화는 분리한다. 실제는 2인 이상 훈련된 평가자가 파형·스펙트로그램·주기를 검토하고 불일치 U를 보존한다. 후보의 출력을 그대로 정답으로 재사용하지 않는다.

- coverage=출력 있는 V/N_V(보류/실패도 분모). 오차는 참조와 출력이 있는 V에서 계산하되 coverage를 함께 보고한다. UV 허위 F0=확신 출력 UV/N_UV, U 확신 출력도 별도 측정한다.
- 시작 gate: V median 절대오차≤0.5반음, >1반음 gross error≤5%, 12·k±1반음(k≥1) 옥타브 오류≤2%, V coverage≥60%, 처음/마지막 정답 방향 일치≥90%(적격 시도 전체 분모, 보류 포함). UV 허위 F0≤2%(95% 상한≤5%), U 확신 출력 0건(95% 상한≤5%)도 동시 요구한다.
- deadband/대역/창·표본/신뢰구간은 T06 전 잠금. 사람/조건별 실패·전체 U 비율을 숨기지 않는다. 0건 표본이 적거나 주석 불안정이면 통과가 아니라 미결정이다.

| 반례 | 기대 출력 |
|---|---|
| 100→200→150Hz | 처음/마지막 +7.020반음, 중간/마지막 −4.980반음. 국소 끝 올리기 성공 금지 |
| 끝 평탄/끝 무성·긴 공백 | 국소 상승 단정 없음. UV/공백에 선 없음, 창 부족 시 방향 보류 |
| 주기적 잡음/반주만 | 사용자 F0로 확신 표시 금지 |
| 후보만 100→200 옥타브 도약 | 독립 참조 100이면 gross/octave 오류·해당 방향 보류. 실제 200 발성은 다른 정답 |
| 평가자도 불확실 | U로 보존, 정답 숫자 발명 금지 |

## 7. 독립 제품 기술 선택·구성·데이터

### 7.1 선택과 기존 코드 재사용 경계

| 대안 | 장점 | 절충/권고 |
|---|---|---|
| TypeScript Web+의미론적 HTML/CSS+Web Audio/Worker | 퀴즈는 단순 로컬 결정 규칙, 설치 없는 Safari, 입력/Worker 한 언어 계약 | **우선 검증안**. Safari 입력/해제·F0가 핵심 위험. 퀴즈는 음성 엔진 없이 독립 |
| Flutter Web | 팀의 실제 Dart 경험이 있으면 재사용 이점 | 기존 앱 때문만으로 유지 의무 없음. JS audio/Worker 브리지 추가 비용 |
| 네이티브 | 오디오 세션/모델 자원 통제 가능성 | 설치/배포/별도 기술 비용. 네이티브도 정확도/적절성 자동 보장 아님. 웹 실패 시 사용자와 범위 재결정 |

기존 `app.dart` 등록 선행·enrollment·WeSpeaker/ONNX 화자 모델은 새 훈련에 필수로 넣지 않는다. 실제 등록 구현은 존재하나 단일 화자 연습의 필요성/대상 성능 미검증이다. 캡처의 epoch/취소·visibility/device 정리 패턴과 자산 출처/고지는 참고하며, 무조건 복사/전체 재사용하지 않는다.

```text
Home / Module selector
 ├─ Quiz UI → QuizSession → reviewed QuizCatalog + deterministic AnswerEvaluator
 │    └─ QuizProgressStore (기본 메모리·선택 로컬 저장, microphone/API 없음)
 └─ Audio practice UI → AudioTrainingSession
      └─ CaptureSession (epoch/settings/고정PCM/해제)
           ├─ ExistingScaleMeter (RNNoise/VAD/+114/2모드 참고선)
           ├─ WholeIntervalLevelComparison (다른척도, reference 분리)
           └─ PitchWorker (독립 검증 후)
```

코드/폴더를 생성한 것은 아니다. 향후 `domain/audio/quiz/content/ui/workers/tests` 경계를 제안한다. 구체 버전·번들러·라이브러리/모델 권리는 구현 착수 시 공식 자료로 확인하고 잠근다. 현재 자동 발음 모델·STT·서버는 필요 없다.

퀴즈와 audio result는 서로 변환하지 않는다. `QuizSummary`로 음소 정확도를 만들 수 없다. 입력 fingerprint는 페이지 내 동일 reported deviceId 여부를 비교하는 임시 토큰이며 외부/영구 식별자로 저장하지 않는다. 재준비 때 식별 불가/변경이면 비교 보류, 새로고침 뒤 과거 기준은 읽기용이며 새 라이브 비교엔 재기준이 필요하다.

8.6초 48kHz float mono는 약 1.65MB/시도(모델/복사본 별도). 최대 A/B 2개 고정 PCM은 Worker 소유·UI에는 handle만; 선택 재생용 일시 버퍼는 완료/취소 해제. quiz는 audio buffer를 만들지 않는다. 첫 방문 HTTPS/앱 자산 다운로드와 로컬 계산을 구분하고 캐시 없음/손상 시 오프라인 사용을 보장하지 않는다.

## 8. 개인정보·저장·권리

- 퀴즈 기본은 로그인/서버/녹음/외부 모델/API 없음. 선택 답과 임시 진행만 메모리. 앱 사용 동의가 음성 수집 동의가 되지 않는다.
- 크기/피치는 마이크가 켜졌음을 표시하고 정상 완료/30초 준비 만료/백그라운드/분석 실패에 수집 종료. 고정 PCM과 캡처 track의 수명은 다르다.
- 저장은 명시 선택. quiz 진행·수치·원음은 별도이고 기본 원음 저장 false. 항목별/전체 삭제·기준 초기화 제공. 브라우저 데이터 삭제/다른 기기 사용/백업 없음 한계를 고지한다.
- JavaScript 참조 해제·버퍼 정리와 물리적 영구 삭제 보장은 구별한다. 다운로드/사용자가 공유한 복사본은 앱이 회수할 수 없다.
- 분석/오류 로그·텔레메트리에 원음·전사·개인 건강/신상·영구 deviceId를 넣지 않는다. 실제 네트워크/저장소 검사를 T08로 수행한다.
- 연구 참여/진행 저장/원음/외부 전송 동의를 앱 사용과 분리한다. 참가자 담당은 사용자이나 자원·연락·동의/철회·보관 기간/접근자는 실제 계획으로 확정돼야 한다. 담당 결정만으로 수집/연구 재사용 허가가 된 것은 아니다.
- 문항/설명/그림/예시 음성/폰트·모델/런타임 권리를 각각 확인한다. 바름의 문구/화면/데이터/모델을 복제하지 않는다. 공식 규칙의 사실을 참고해 자체 문항을 쓰며 제3자 표현/자산의 재배포 허가를 별도로 확인한다.
- 앞으로 외부 분석을 넣는다면 제공자·전송 정보/국가·보관/학습 사용·삭제·비용·대안을 확인하고 구체 동의를 다시 받는다. 지금 제품에 자동 업로드 fallback을 넣지 않는다. API 키/개인 자료를 GitHub에 올리지 않는다.

### 9.1 가장 가까운 대안 선정

- 시험 직전 실제 접근 가능한 앱/교재를 공식 자료로 확인하고 언어·기기·비용·허가·개인 설정·피드백/복습 흐름을 기록한다. 구매/설치/기관 접촉은 별도 승인 전 하지 않는다.
- 크기/피치는 **Voice Trainer 등 개인 기준+시각 피드백이 있는 실제 도구**를 우선 검토한다. 단순 빈 그래프를 주 비교로 삼아 유리하게 만들지 않는다.
- 발음 퀴즈는 현재 가용한 한국어 발음 선택/설명 학습 도구와 **같은 콘텐츠를 읽는 학습 카드**를 비교 후보로 한다. 바름이 현행 퀴즈 앱이라고 가정하지 않는다. STT/녹음은 퀴즈와 같은 기능 대안이 아니라 별도의 기존 방법이다.
- 실제 앱이 언어/기기/허가상 불가하면 이유를 남기고 핵심 능력/학습량을 맞춘 합법 조건을 쓴다. 이때 ‘해당 실제 제품보다 우수’라는 주장은 하지 않는다.
- 참가자가 쓰던 dB/녹음/교재/도우미 방법도 별도 기준이며 도움 시간/비용·준비 부담을 함께 기록한다. 접근 장벽이 있다는 사실만으로 새 앱 비교를 통과시키지 않는다.

### 9.2 T07 행동 코딩과 추가 가치

| 코드 | 크기/높낮이 과업 | 퀴즈 과업 | 실패 예 |
|---|---|---|---|
| K1 범위 이해 | 척도≠적정 SPL, F0 차이≠올바른 억양을 자기 말로 설명 | 문항 정답≠내 목소리 발음 평가를 설명 | 숫자/정답 표시를 정상 발음/의학적 보증으로 해석 |
| K2 불가 대응 | 조건 변경/손실/무성·불확실에 재기준/중지 | 모호 문항/버전 수정/모르겠음에서 채점 보류·skip/제보 | 비교 불가를 성공으로 해석, 잘못된 문항을 본인 발음 탓으로 해석 |
| K3 다음 한 행동 | 자기가 원한 방향의 한 조절·입력 조건 유지 | 한 규칙/설명을 선택해 새 예제에 적용 | 연구자 도움/무조건 큰소리, 정답 위치 암기만 |
| K4 결과 확인 | A/B의 변화/아직 아님/판단 불가를 독립 참조와 일치해 해석 | 새 예제의 정답 이유/허용 변이를 설명하고 무엇을 복습할지 선택 | 화면만 완료·호감은 있지만 의미/다음 학습을 모름 |

- K1~K4를 모두 도움 없이 충족해야 자율 유효 행동 성공이다. quiz는 발화/재청취 없이 가능해야 한다. audio는 원하는 변화가 안 생겼음을 정확히 알고 멈추는 것도 적절한 K4지만, 실제 원한 음향 변화가 생긴 비율을 별도 보고한다.
- 초기 절대 기준: 범위/보류 의미 이해≥80%, 자율 유효 행동≥70%, 무효 개선·진단/발음 정상 오해에 따른 위험 행동 0건. 퀴즈 정답/설명 점수는 별도 지식 지표이며 이 비율로 발화 향상을 대체하지 않는다.
- 추가 효용 초기 기준: 가까운 대안 대비 자율 유효 행동 +20%p 이상, 대응 비교 사람 단위 95% 하한>0, 위험 오해 증가 없음. 준비/읽기/피로 비용을 함께 판단한다. 8–12명은 탐색 시작 표본이지 확증 검정력 보장이 아니다. 부족하면 미결정/재설계이지 통과가 아니다.
- 퀴즈 학습 주장을 하려면 같은 문항 재시도 상승이 아닌 동등 난이도 새 예제의 첫 답·규칙 설명을 사전 정의하여 비교한다. 단지 정답을 재표시한 효과/읽기 능력/보기 길이 단서를 통제한다. 퀴즈가 교재보다 도움이 없거나 부담만 크면 인터랙션 재설계/제품화 보류다.
- 사용자와 평가자 확보는 사용자가 담당하기로 했으나, 인원·동의·독립 코더·콘텐츠 검토자·기기·시간은 아직 확보 완료가 아니다. 모집 실패는 실증 gate의 실제 blocker다.

| Q05 차별성 | 사용자도 아직 모름. 가까운 대안 대비 추가 가치 미검증 | 마케팅 주장 안 함. T07 비교로 판단 |
| Q06 최종 설계/다음 실행 | r3 재검토 후 승인 요청 예정 | 제품 구현·설치·녹음 수집·배포 착수 안 함 |
| Q07 저장/장기 기록 | 필수 요구 미확인 | quiz/음성 기본 미저장, 계정/클라우드 만들지 않음 |

Astra 독립 AI 검토는 최신 사용자 변경에 맞춘 **설계 논리·안전 경계·검증 계획**을 승인했다. 실제 교수/임상전문가/당사자의 인증, 제품 작동·실제 수요·지식/발화 효과·제품화·배포의 승인이 아니다. 과거 자동분석 전용 P0/성능 gate는 사용자 변경으로 적용 종료했으며, 실증으로 해결됐다고 기록하지 않는다. 새로 필요한 문항 검수·접근성·지식/효용·실기기·동의/삭제 gate는 남아 있다.

말결의 제품 구현/다음 실험 범위는 사용자 최종 확인 후 정한다. 특히 피치에는 확인된 기존 수치가 없으며 상대 시각화는 새 연구 제안이다. 추가 숫자나 정상 판정을 몰래 넣지 않고, 이 사실 때문에 이미 정한 퀴즈·책상 위 방향을 다시 질문하거나 설계 전체를 중단할 필요는 없다. 새 제품 기능의 실질 변경은 다음 revision과 영향 검토를 거친다.

출판 대상은 `h-gunp/voicewow`의 `docs/speech-training-design-20261102` **문서 전용 브랜치**다. 안정적인 기존 문서 링크를 위해 정식 파일명 `docs/speech-training-design/2026-11-02-voicemate-training-design.md`는 유지하며 본문 제품명은 말결로 구분한다. 출판 담당자는 문서-only diff·상대 링크·원격 내용/SHA를 확인한다. 이 설계 문서의 갱신은 말결 코드/main 병합/사이트 배포나 기존 VoiceMate 배포의 완료를 뜻하지 않는다.

이전 승인 release와 고정 r3 원본/검토 영수증은 보존한다. 원본 revision·내부 작업노트는 비공개로, 공개 설계/검토/수정응답에는 원문 전사·개인 건강/신상/연락처·비밀을 넣지 않는다. 실제 실패 결과를 숨기거나 기준을 낮춰 이 승인을 재사용하지 않는다.

검토 방법: 자문 요약의 관찰/해석 대조, 실제 코드/설정 확인, 경쟁/공식 언어규범 확인, 최신 요구 추적과 독립 설계 비판. 문헌·서지/설명 확인과 실증을 구별한다. 제품/마이크 시험·사용자 조사·전체 콘텐츠 검수·임상/장기연구는 실행 완료가 아니다.
