## 문서 반례 계산 결과

`reviews/r2-document-check.txt`는 문서의 수식·판정 규칙에 인공 숫자를 대입한 **문서 검증**이다. 모델/사용자/마이크 테스트 결과가 아니다.

1. 허용 A 1,000개를 모두 목표유사 C, 오류 E 1,000개 중 900개를 C/100개만 오류후보 D로 내면, D precision 100%여도 C precision 52.6%, 거짓수용 90%, E recall 10%로 **실패**한다.
2. 전부 보류는 군별 coverage/recall 0%·precision 정의불가로 통과할 수 없다. 허용군만 C를 내면 E coverage/recall 0%로 실패한다.
3. 전문가 불확실 100개에 확신출력 100개인 경우 안전셋 조건에 실패한다.
4. F0 100→200→150Hz는 처음/마지막 +7.020반음, 중간/마지막 -4.980반음이다. 현재 기능의 이름·출력은 전자이며 국소 ‘끝 올리기 성공’을 만들지 않는다.
5. 프레임 크기 `[.01,.01,.01,.10]`을 절반으로 줄였을 때 `.007` 미만을 빼면 선택 median은 +13.979dB로 뒤집힌다. 전체 구간 에너지는 실제대로 -6.021dB다. 실제 파형+VAD/품질 E2E 시험은 별도 필수다.
6. UI 완료/호감만 있고 K1/K3/K4를 실패한 참가자는 자율 유효행동 성공으로 세지 않는다.
7. Markdown fence·E/A/R/D/T/Q ID 범위·내부 작업문구 제거·핵심 수정 계약의 존재를 확인했다. 이것은 문서 내용의 정합성 확인이지 제품 기능의 통과 판정이 아니다.
