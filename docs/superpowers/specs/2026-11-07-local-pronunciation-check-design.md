# 기기 내부 발음 비교 설계안

상태: 사용자가 2026-11-07 “좋아 진행해”라고 답해 이 설계와 로컬 모델 검증 → 화면 교체 순서를 승인했다. 시작 기준 코드는 `530895d`다. 실제 실행과 정확도 검증 결과는 후속 계획에 기록한다.

후속 지시: 사용자가 “남은 작업 이어서 해줘 실제 발음 판별 검증은 추후에 완성되면 내가 직접할게”라고 요청했다. 따라서 실제 발음 정확도 검증을 제품 연결의 선행 조건으로 두지 않는다. 녹음·모델 추론·표기 비교·기존 화면 교체까지 구현하고, 사용자가 완성된 화면에서 검증한다. 아래 선행 검증을 요구한 부분은 이 지시로 변경된다. 색은 **모델이 추정한 발음과 참고 발음의 일치/차이**이며 실제 정오나 임상적 정확도라고 표현하지 않는다. 판정할 수 없는 표기·음소·참고 구간은 회색으로 남긴다.

## 목적과 확정한 요구

선다형 발음 퀴즈를 자신이 말한 발음과 기준 발음을 비교하는 연습으로 바꾼다. 사용자가 기존 단어 또는 저장한 문장을 선택하고, 상세 화면 하단 마이크를 한 번 눌러 녹음하고 다시 눌러 종료한다. 결과는 인식된 발음을 한글로 보여 주고 일치·차이를 글자별로 표시한다. 다시 읽으며 교정하는 것이 목적이다.

사용자는 음성 분석을 기기 내부에서만 처리하도록 선택했다. 음성·인식 결과·선택 문장을 외부 분석 서버로 보내지 않는다. 모델 파일을 처음 내려받는 것과 음성을 전송하는 것은 구분한다. 다운로드 크기와 캐시 상태를 녹음 전에 안내한다.

현재의 초록·중립색 디자인, 음량 측정, 높낮이 연습, 저장한 문장과 북마크는 유지한다. 참고 이미지에서는 정보 순서와 하단 마이크 동작을 가져온다. 노란색 테마나 발음과 별개인 음량 권장 막대를 추가하지 않는다.

## 접근 방식과 판단

| 방식 | 확인한 특성과 판단 |
| --- | --- |
| 기존 로컬 ASR의 문장과 정답 문자열 비교 | 기존 워커를 재사용하기 쉽지만 현재 앱 출력은 문장 전사다. 발음이 문맥에 의해 보정되거나 전사 자체가 틀릴 수 있으므로 실제 발음 정오 판정으로 쓰지 않는다. |
| 로컬 한국어 음소 인식 후 기준 음소와 비교 | 요청한 발음 차이를 직접 다룰 수 있는 후보 방식이다. 모델 실행 성능, 음소 구별, 한글 표시, 오판율 검증이 필요하다. 구현자가 제안하는 방식이다. |
| 외부 발음 평가 API | 사용자가 선택한 기기 내부 처리 제약에 맞지 않는다. 후보에서 제외한다. |

사용자가 직접 정한 제약은 로컬 처리다. 구체적인 모델 후보·단계·회색 표시·저장 정책은 구현자 제안이며, 위 승인으로 진행할 설계에 포함됐다. 모델 적합성이 검증됐다는 뜻은 아니다.

## 현재 코드에서 재사용할 부분

- `quiz_catalog.dart`의 125개 콘텐츠 ID·분류·원문·출처와 기존 목록 UI를 재사용한다. `pronunciation` 단일 문자열을 모든 허용 발음의 완성된 정답 집합으로 취급하지 않는다.
- `learning_store.dart`의 `voicemate.pronunciation.v1`, 북마크, 최대 60개 개인 문장을 보존한다. 과거 `answers`와 `wrong`은 선다형 기록이며 말하기 성공·실패로 바꾸어 해석하지 않는다.
- `PronunciationGuideEngine`은 참고 읽기를 만든다. 어절 사이 음운 변화와 모든 예외를 지원하지 않으므로 개인 문장의 완전한 채점 기준으로 사용하지 않는다.
- 기존 예시 듣기와 TTS 취소·소유권 처리를 재사용한다. 새 발음 화면에서는 로컬 한국어 음성만 선택하며 로컬 여부를 확인할 수 없으면 듣기를 사용할 수 없다고 표시한다. 음성 재생 실패로 텍스트와 녹음까지 막지 않는다.
- Android의 `DeviceAudioService`는 16kHz 모노 PCM 녹음·20초 제한·정리를 제공한다. 네이티브 음소 추론은 현재 없다.
- 웹의 PCM 작업과 워커 수명 관리 패턴을 재사용하되, 높낮이의 스트리밍 ASR과 발음 비교를 같은 결과로 취급하지 않는다. 현재 ASR stop은 미전달 tail을 버리고 워커를 종료하므로 발음 결과 확정 경로로 그대로 쓰지 않는다.

## 화면과 사용자 흐름

1. `발음 퀴즈` 탭을 `발음 연습`으로 바꾸고 기본 단어·문장 목록에서 선택하게 한다. `내 문장`과 저장 목록에서도 같은 상세 화면으로 들어간다. 선택지·정답 제출·퀴즈 점수 대신 읽기 연습을 보여 준다.
2. 상세에는 원문, 기준 발음 또는 참고 읽기, 예시 듣기, 결과 영역, 하단 마이크를 배치한다. 모델 준비 중과 오류 상태를 보여 주고, 준비가 끝나기 전에 녹음을 시작하지 않는다.
3. 첫 마이크 입력은 녹음 시작이다. 녹음 상태와 경과 시간을 표시한다. 재입력 또는 20초 제한으로 종료하고 마지막 샘플까지 한 번 분석한다. 권한 거부·무음·너무 짧은 입력·중단은 재시도 가능한 별도 상태다.
4. 결과 제목은 `인식된 내 발음`이다. 모델이 추정한 표기임을 짧게 알린다. 녹색은 검증된 기준과 일치, 빨간색은 차이 감지, 회색은 판정 보류다. 색뿐 아니라 밑줄·기호와 읽을 수 있는 설명을 제공한다.
5. 결과 아래에는 `기준 께 → 인식 떼`처럼 확인 가능한 차이만 보여 준다. 빠진 소리는 기준 줄에 누락 표시를 두고, 추가로 말한 소리는 결과 줄에 추가 표시를 둔다. 한 글자 누락 때문에 이후 문장 전체가 빨간색으로 밀리면 안 된다.
6. 하단에서 다시 녹음하거나 자신의 녹음을 기기 안에서 다시 듣는다. 새 시도는 이전 결과를 대체한다. 숫자 점수, 순위, 완료율, 새 영구 기록 기능은 추가하지 않는다.

좁은 화면과 글자 200% 확대에서 결과는 스크롤되고 마이크·뒤로가기를 사용할 수 있어야 한다. 결과가 화면 밖으로 가려지는 고정 높이는 사용하지 않는다.

## 음성 분석 경로

`녹음 PCM → 16kHz 모노 전처리 → 기기 내 CTC 음소 모델 → 음소 열 → 허용 기준과 정렬 → 한글 표시·차이`

첫 검증 후보는 `slplab/wav2vec2-xls-r-300m_phone-mfa_korean`을 ONNX int8로 변환한 `chegrowk/ko-phone-int8`이다. 원모델 카드와 변환본은 Apache-2.0을 표시한다. 변환본은 356,129,122바이트이며 원모델의 약 1.26GB PyTorch 파일보다 작다. 가중치 크기가 실제 실행 메모리 크기와 같다는 뜻은 아니다.

- 원모델 revision: `e26ff9dfb62169acf445d0060ef56863c018b20e`다.
- 변환본 revision: `dbb9c196f3e5e72d41c8ce2b63e6d0c91a011b70`다.
- 변환자는 opset 17, MatMul 대상 per-channel dynamic int8, 원본 tokenizer·전처리 설정 복사를 명시한다. 실제 다운로드 때 가중치 해시와 라이선스를 확인하고 출처를 함께 기록한다.
- 웹은 이미 저장소에 있는 `web/prosody/vendor/onnx/ort.wasm.min.mjs`를 전용 Worker에서 재사용하고 CPU/WASM부터 확인한다. 새 Transformers.js 파이프라인을 추가하지 않는다. 현행 앱에서 이 모델의 실행 성공은 아직 확인하지 않았다. 지원되지 않거나 메모리가 부족하면 명시적 준비 실패로 끝낸다. 외부 API나 브라우저 원격 음성 인식으로 전환하지 않는다.
- Android는 기존 녹음 PCM에 공식 `onnxruntime-android`와 Kotlin MethodChannel을 연결하는 별도 검증 대상이다. 현재 네이티브 ONNX 의존성은 없다. 웹 성공을 Android 성공으로 보고하지 않는다. 현재 사용 중인 웹에서 후보를 검증한 다음 Android를 검증하는 순서는 구현자 제안이다.
- 첫 단계는 녹음 종료 뒤 전체 발화를 처리하는 방식이다. 높낮이 ASR의 endpoint 누적·실시간 확정 프로토콜을 바꾸지 않고 현재 녹음 버퍼를 끝까지 전달한다. 웹 전용 녹음기를 만들 때도 사용자 stream 하나만 열고 종료 응답을 받은 뒤 분석한다.
- CTC 출력은 정답 문장으로 강제 교정하지 않는다. 기준 문장은 분석한 음소와 비교하고 표시할 위치를 정하는 데 사용한다. 모델에 없는 음소 구별을 정답에서 복원하지 않는다.
- 고정 revision의 설정에 맞춰 16kHz 모노를 정규화하고 attention mask를 처리한다. 실제 ONNX 입출력 이름·shape·연산자 호환은 첫 실행 때 확인한다. CTC의 연속 중복을 축약하고 blank를 제거하되 blank로 나뉜 반복 음소는 보존한다. 특수 토큰·NaN·비정상 길이를 검증한다. 현재 사전은 한글 글자가 아닌 MFA phone 40종과 특수 토큰이며, blank는 설정의 `[PAD]` ID 42다. 생성된 Hugging Face pipeline 예시를 실제 tokenizer 호환 검증으로 보지 않는다.
- 추론 로짓이나 softmax 값을 곧바로 발음 정확도 백분율로 사용하지 않는다. 소음·왜곡·모델 불확실성·정렬의 모호함을 판정 보류로 보내는 정책은 실제 표본으로 정한다.

## 기준 발음과 한글 표시

비교 단위는 띄어쓰기와 맞춤법이 아니라 음소다. 기준 원문·허용 발음 집합·출처·채점 가능한 범위를 분리한다. 같은 소리의 표기 차이와 허용 변이는 오답으로 표시하지 않는다. 사용자가 제시한 `맛있게`는 `[마딛께]`와 `[마싣께]`를 모두 허용한다.

기본 콘텐츠는 출처와 음운 변화를 검토한 항목부터 비교 가능하게 한다. 모든 기존 단어와 개인 문장은 선택·듣기·녹음을 유지하지만, 검증한 기준이 없거나 지원하지 않는 변화가 있으면 `참고 읽기`와 `판정 보류`로 표시한다. 이 경우 잘못된 기준으로 빨간색·녹색 결과를 만들지 않는다. 개인 문장 전부를 정확히 평가하는 문제는 이 제한을 숨기는 UI로 해결하지 않는다.

모델의 phoneset을 먼저 확인하고 자모와 초성·중성·종성으로 매핑한다. 평음·경음·격음, 받침, 모음 등 실제 출력에서 구별되는 범위만 비교한다. 음절 경계가 모호하거나 한글 음절로 만들 수 없는 출력은 자모 또는 불확실 표시로 남기며 임의의 모음을 채우지 않는다. 기준과 비교한 정렬이 복수로 동등하면 해당 범위의 차이를 확정하지 않는다.

허용 기준마다 삽입·탈락·대치를 정렬하고 가장 적합한 허용 기준을 선택한다. 한글 결과의 음절마다 원래 음소 범위를 보존한다. 초성 하나의 차이는 해당 음절을 표시하며 원문과 표면 발음의 글자 수가 다를 수 있음을 다룬다. 모델이 구분하지 못하는 모음 등을 반드시 구분한 것처럼 보여 주면 안 된다.

## 녹음·데이터 수명

상태는 준비, 대기, 권한 요청, 녹음, 분석, 결과, 오류로 제한한다. 녹음 시작 전에 진행 중인 TTS와 다른 기능의 마이크 정리를 기다린다. 준비·권한 요청·분석 중 연타를 잠그고 모든 비동기 결과에 세션 ID를 붙인다.

뒤로가기, 항목 변경, 탭·기능 이동, 앱 이탈은 녹음을 취소하고 스트림·워커·재생을 정리한다. 이전 세션의 늦은 권한 허용이나 분석 결과가 화면과 마이크를 되살리지 않아야 한다. 종료하여 분석하는 동작과 취소하여 버리는 동작을 분리한다.

녹음·음소·결과는 이번 상세 화면의 임시 상태다. 화면 종료·재시도 때 이전 오디오 객체와 임시 파일을 정리한다. 서버 전송·분석 로그 업로드·영구 음성 저장은 없다. 모델 캐시만 로컬에 유지한다. 기존 학습 저장 키의 버전과 내용은 유지한다. 복습의 과거 퀴즈 기록은 과거 기록임을 구별하고 선택하면 새로운 발음 상세로 연결한다.

## 검증 순서와 완료 조건

1. 모델·tokenizer·phoneset·라이선스를 고정하고 로컬 입력 한 개의 추론부터 검증한다. 이 단계에서는 제품 화면을 바꾸거나 기존 퀴즈를 제거하지 않는다.
2. 정상 발음과 의도적으로 다르게 말한 실제 녹음을 따로 준비한다. 녹음자가 읽으려던 문장이 아니라 사람이 들은 소리로 표기를 확인한다. 평음·경음·격음, 받침·연음, 모음, 삽입·누락, 두 허용 발음, 무음·잡음을 포함한다. 사용자 음성을 자동으로 수집하지 않는다.
3. 한쪽 표본으로 정책을 조정하고 별도 표본에서 오답 표시의 거짓 양성, 오류 놓침, 판정 보류 비율을 각각 보고한다. 출처 모델의 PER 수치를 앱 정확도로 바꾸어 주장하지 않는다. 필요한 실제 녹음이 없으면 정확도 검증은 미완료로 둔다.
4. 사용자 예시의 `께/떼`, `써/떠` 같은 구별을 실제 입력에서 보존하는지 확인한다. 인식기가 이를 교정해 지워 버리거나 안정적으로 구분하지 못하면 해당 결과를 확정 색상으로 출시하지 않는다. 실패하면 모델 변경 또는 추가 학습이 필요한 상태로 보고한다.
5. 웹에서 첫 다운로드 크기·시간, 캐시 재사용, 준비 시간, 5초·20초 녹음의 추론 시간·메모리·취소를 측정한다. Android는 별도로 측정한다. 실제 측정 전 모바일에서 원활하다고 주장하지 않는다.
6. 분석 경로가 검증되면 목록·상세·재녹음을 연결하고 기존 퀴즈 UI를 교체한다. Flutter에서 허용 변이·정렬·저장 호환·화면 이동·권한 대기 취소·확대 글자를 검사한다. 웹에서 최종 샘플 포함·무음·오류·연타·화면 이탈·늦은 결과·모델 준비 실패를 검사한다.
7. 기존 음량·높낮이·TTS의 테스트, 정적 분석, 웹 빌드를 실행한다. 실제 브라우저 마이크·비행기 모드 또는 네트워크 차단 후 추론·외부 요청 부재를 별도로 확인한다. 합성 입력·단위 테스트·빌드 성공을 실제 음향 정확도로 보고하지 않는다.

## 변경 예상 범위

주요 호출부는 `pronunciation_screen.dart`, `quiz_training_view.dart`, 개인 문장·복습 상세 진입, `app.dart`의 기능 전환 정리다. 모델 서비스·녹음 연결·음소 비교와 해당 테스트를 추가한다. `learning_store.dart`의 기존 스키마를 변경하지 않으며 새 말하기 점수 스키마도 만들지 않는다.

영향받는 검사는 `pronunciation_quiz_ui_test.dart`, `personal_guide_ui_test.dart`, `learning_store_test.dart`, `speech_controls_test.dart`, `app_test.dart`, `interface_layout_test.dart`다. 기존 높낮이 ASR 클라이언트와 PCM 브리지를 실제로 수정한다면 그 회귀 테스트도 함께 실행한다. 가중치는 git에 넣지 않고 고정된 출처·해시·캐시 정책만 관리한다.
